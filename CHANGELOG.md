# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html) (while below 1.0.0, a minor bump may break things).

Every change goes under `## [Unreleased]` as it is made. Publishing renames that section to the new version and date (see `ENV.md`).

## [Unreleased]

### Added
- Quality tiers (T-48, QUESTIONS PRF-2; `params/quality.toml`, `src/quality.rs`, menu panel Performance): `quality_tier` = `exact` (the evaluation as before the tiers, bit for bit), `standard` (default: the beam of an unscaled flat tube on the line-image path, within one FP16 step of exact, `screen` 2.4 to 3 times cheaper on flat tubes), `fast` (also amplifier sub-samples capped to the host pixels per source pixel, at least 4, and the line-image path on scaled flat rasters; within 0.82 % of white mean, 2.7 % max), `low` (also a beam reach of 3 sigma, specialization constant 1 of `beam.glsl`, and a coarser warp grid; within 0.87 % mean, 2.7 % max). A tier changes cost parameters only, never a look parameter; a preset change keeps it. Measured cost and error per tier: ARCHITECTURE 3.7 "Quality tiers".
- Automatic quality drop on sustained overrun (QUESTIONS OUT-6; `quality::AutoQuality`, pure and unit tested): with `quality_auto` (off by default) the tier in force drops one step after 3 s of GPU frame time above the refresh period of the output's monitor (`output::refresh_hz`), and comes back one step after 10 s below 65 % of it (the wait doubles, up to 160 s, after a relapse within 30 s); the parameters are not changed (`Renderer::set_quality_drop`), the console, the window title and the overlay (row "Quality") show the tier in force.
- `tests/perf_profile.rs` (ignored): the whole chain per stage, headless, at 1280 x 720, 1920 x 1080 and 2560 x 1440, defaults and presets 01 (flat and cylindrical) and 05, five contents, interleaved rounds; `tests/quality_tiers.rs`: each tier against `exact` on five configurations and four contents.
- `ultimatecrt --detect-bars <png>`: offline picture-area diagnostic on a `--save-capture` PNG (the picture and bars found, the reason when nothing is cropped, per-edge statistics, the old rule for comparison); no window.

Hotkeys and output modes (T-54, T-57)
- Global hotkeys by `RegisterHotKey` on the output window (`src/hotkeys.rs`, no keyboard hook): Quit `Ctrl+Alt+Q` (fixed), fullscreen and framed window `F11`, settings menu `F10` (D-17: F12 is owned by another program on the dev machine, error 1409), overlay `Ctrl+Alt+O`, A/B bypass `Ctrl+Alt+B`, next and previous preset `Ctrl+Alt+PageDown` and `Ctrl+Alt+PageUp`. Chords are configurable in `[global.hotkeys]` of `settings.toml` (`Mod+Mod+Key`, case-insensitive, validated: unknown keys, repeated modifiers, bare ordinary keys, collisions and a rebound quit give a warning and the default); a chord another program owns falls back along a short per-action list (the menu: `F10`, `Ctrl+Alt+F10`, `Ctrl+Alt+F12`) and the console line names the chord and the Win32 error (`Registration::problems`, `has_problems` for the UI). The registration plan and the fallback logic are pure and tested with a fake registrar. `WM_HOTKEY` becomes `Action`s in a queue (`output::take_actions`).
- `controls.rs`: pure dispatch of the actions, the `UiHook` contract with the settings UI (`NoUi` stand-in for the tests), preset next and previous (`step_preset`: tube parameters replaced, the `source` group kept), and the A/B bypass plan (every chain slot off, the earlier flags restored on the way back; `Renderer::stage_names` and `stage_enabled`).
- Output modes (`modes.rs`, `live.rs`, `output::apply_placement`): F11 toggles the borderless non-activating fullscreen output and a framed, resizable, non-activating window (the swapchain follows the size); the window rectangle is remembered in `[global.output] windowed` of `settings.toml` and restored while it is still on a monitor; the output re-places itself on `WM_DISPLAYCHANGE` and follows `WM_DPICHANGED` when framed; the host cursor is hidden over the picture while the menu is closed. `lifecycle::LostWatch::set_fullscreen`. Not implemented: the click-through option (no command-line flag yet).
- `scripts\check-hotkeys.ps1`: live check of the chords and of F11 against the independent focus monitor (needs a hands-off desktop; not yet run).
- Settings menu wired to the hotkeys and the output modes: `ui::Ui` implements `controls::UiHook`, so the menu key (default F10, fallbacks Ctrl+Alt+F10 and Ctrl+Alt+F12) opens and closes the menu with its focus hand-off and Ctrl+Alt+O shows or hides the overlay. One function, `output::sync_activation`, sets `WS_EX_NOACTIVATE` and the T-07 hand-back from the window mode and the menu state together (`effective_no_activate`, unit tested): the open menu makes the output activating in any mode, F11 still toggles fullscreen with the menu open (the menu stays usable), closing the menu restores the behaviour of the current mode. While the menu is open Esc closes the menu and gives the foreground back instead of closing the output; Ctrl+Alt+Q and the other hotkeys keep working. The menu shows the hotkey registration problems (a chord owned by another program, the fallback in force, an action left without a hotkey) under its key hint, and the key hint names the chord actually registered. The hotkeys, the window rectangle and the menu layout share one settings instance (`live::Live` owns it; the UI hands its layout back through `Ui::take_layout_change`, so a window-rectangle save no longer overwrites a newer layout or the reverse); the preset selected in the menu is the one the preset hotkeys step from, and the menu shows the preset a hotkey stepped to. A menu still open at exit gives the foreground back and its layout is saved. Not yet validated live.

Pipeline and physics (each stage has an oracle in `crt-model` and analytic GPU tests)
- Pipeline core: an FP16 `decode` stage (compute, native raster read at block centres) and an `encode` stage (explicit host EOTF, black surround around the tube rectangle), two frames in flight with per-frame uniform and staging buffers, images reallocated on source or native size change. Headless identity tests: all 256 codes per channel come back exact through the FP16 raster, FP16 subnormals kept.
- Source decode and tube placement (T-30): parameters `source_eotf` (`drive_voltage` default, or `srgb`: decoded to linear light, then drive voltage = L^(1/tube gamma)), `raster_aspect` (`par` default or `fill_tube`), `source_par`, `line_multiplier` (1 or 2), and the tube `tube_visible_height_mm` (290), `tube_aspect` (4:3) and `tube_height_fraction`. The CPU fills `px_per_mm` and `line_pitch_mm` of the frame constants (PVM-20M4U class on 2560x1440: 4.966 px/mm, 1.208 mm line pitch). With the defaults the picture is placed exactly as the old letterbox.
- Composite video (T-31, `signal` slot before the amplifier, `shaders/composite.comp`, `params/composite.toml`, oracle `crt_model::composite`, tests `tests/stage_composite.rs`; QUESTIONS PHY-9), optional, `composite_enable` off by default (the slot is skipped, bit for bit unchanged). NTSC or PAL composite or S-Video encode and decode of each native row at the source pixel clock (`amp_pixel_clock_mhz`), 8 samples per pixel: subcarrier phase per pixel, per line (180 degrees for NTSC timing) and per frame (`composite_frame_advance_deg`, 180 or 0: dot crawl), optional channel low-pass with burst-referenced colour gain, notch or 1-line comb separation (PAL: chroma delay line), I/Q (or U/V) chroma bandwidths, tint and colour. Gives chroma bleed, cross-colour (the artifact colours of 8-bit era games) and dot crawl. In the "Signal and amplifier" menu panel.
- Video amplifier (`amp` slot, `shaders/amp.comp`, `params/amp.toml`): Gaussian low-pass of the drive voltage before the gun law (`amp_bandwidth_mhz`, `amp_pixel_clock_mhz`), asymmetric rise/fall (`amp_fall_rise_ratio`), optional peaking (`amp_peaking_gain`, `amp_peaking_mhz`), K sub-samples per native pixel each holding the exact box mean of the amplifier output, clamped to the local input range (slew limiter); the defaults are an exact zero-order hold. Oracle `crt_model::beam::gaussian_step_box_mean`.
- Gun law and white balance (`gun` slot, `shaders/gun.comp`, `params/gun.toml`): `gun_law` power (default, 2.4), gog (contrast, brightness, per-gun cutoff and drive), bt1886 (Lw, Lb) and bt1886_annex1; optional white retune relative to the tube white, to the target `gun_retune_white_xy` (`gun_white_balance`, default off; gains (1, 1, 1) when the target is the tube white); the `srgb` source mode inverts the nominal curve of the active law and `gun_gamma` is clamped to >= 0.1; a disabled `gun` slot shows V as linear light, which is lighter than the gun-on picture. Oracle `crt_model::gun`.
- Automatic beam limiting and raster breathing (`abl` slot after `gun`, `shaders/abl.comp` and `shaders/reduce.comp`, `params/abl.toml`, T-35): the frame's mean beam current (GPU reduction, FP32) is low-passed on real frame times (`abl_tau_s`, default 0.1667 s) and lowers the beam current of the next frame above `abl_threshold_ma` (1.4 mA) with g = 1 / (1 + k max(0, I - I_th)), k set by `abl_full_white_ratio` (0.5); raster breathing `raster_scale` = 1 + `abl_breathing` (APL - `abl_breathing_ref`), used by the geometry stage (T-37); `abl_probe` diagnostic. Off by default (exact identity). Oracle `crt_model::abl`.
- Beam, vertical scanline profile (T-36a): each native row is drawn as a scanline whose Gaussian spot (plus an optional wide tail) is integrated over every host pixel, with the flat-field brightness independent of the spot width. Parameters `beam_fwhm_mid_mm` (default 0.45 mm), `beam_tail_weight`, `beam_tail_sigma_ratio`. Active once the tube is placed (px per mm and line pitch set); until then the screen stage keeps the nearest-sample copy.
- Beam, horizontal spot and spot growth (T-36b): along each scanline the amp samples are blurred by the same round spot and integrated over every host pixel (energy per source pixel conserved, flat fields unchanged), and the spot widens with each gun's beam current, FWHM^2 = d0^2 + k I^(2n). Parameters `beam_fwhm_peak_mm` (default 0.8 mm, PVM-20M4U) and `beam_growth_exponent` (default 0.5); `beam_fwhm_mid_mm` is the width at mid drive (beam current 0.5^2.4). Per-channel convergence hook in `beam.glsl`.
- Beam quality (T-36c): `beam_quality` `standard` (default, separable per workgroup tile, within 0.5 % of white mean of the exact form on the test patterns) or `reference` (exact 2D sum of every sample's own spot).
- Mask (T-39a, T-39b, T-39c): every host pixel takes the exact area average of the R, G and B phosphor elements it covers (pitch, fill and edge softness in physical units), normalised so that flat white keeps its brightness. `mask_type` selects the aperture grille (with optional damper-wire shadows), the slot mask (`mask_slot_period`, `mask_slot_bridge`) or the delta dot mask (`mask_dot_fill`). Below 3 host pixels per triad (and the matching limits vertically) the mask is averaged out by default (no host-grid moire), with a blend band `mask_tier_blend` and `mask_tier` to force either behaviour. Parameters `mask_enabled`, `mask_pitch_mm` (default 0.31 mm), `mask_stripe_fill`, `mask_edge_softness`, `mask_damper_count` (default 0), `mask_damper_width_mm`, `mask_damper_edge_mm`.
- Phosphor saturation (T-40, `phosphor_saturation`, off by default): L = I / (1 + s I) per channel before the persistence history.
- Phosphor persistence (`phosphor` slot, `shaders/phosphor.comp`, `params/phosphor.toml`, T-41): optional frame-to-frame afterglow from the measured P22 decay (Kuhn 2002): a bright frame leaves a green and blue trail of about 5.4 / 4.7 % of its light one frame later at 60 Hz, then about 3 % and 2 %, red none; a static picture keeps its brightness. Parameters `phosphor_persistence` (default off: the picture passes unchanged), `phosphor_frame_rate_hz` (60, the output refresh rate) and `phosphor_tail_strength_rgb` (0.07 to 1). The afterglow is cleared on a source size change and on a new capture session. Oracle `crt_model::phosphor::DecayFit::frame_feedback`.
- Geometry and convergence (T-37, `shaders/include/geometry.glsl`, `params/geometry.toml`): optional curved faceplate (`geometry_curvature` flat, spherical or cylindrical, `geometry_radius_mm`, `geometry_eye_distance_mm`; the raster lies on the surface uniform in arc length), residual pincushion/barrel, trapezoid and rotation, overscan per axis, and per-channel misconvergence (static dx, dy in mm plus a radial term growing toward the corners). ABL raster breathing (`abl_breathing`) now resizes the picture about the tube centre. The mask stays fixed on the tube. Every default is the identity: the picture is unchanged. The tube image carries a margin around the raster (`raster_margin`, 4 sigma of the spot at twice the peak current plus the largest misconvergence, limited by the room in the output) where the spot's skirt is drawn instead of cut; the live output adds it whenever the `screen` slot runs (a bypassed `screen` has no skirt and no margin). The `standard` beam quality keeps its separable fast path for the margin, overscan, `raster_scale` and misconvergence; a curved faceplate, pincushion, trapezoid or rotation made it fall back to the `reference` evaluation (the cost of `reference`) until T-91 (see Changed).
- Visible opening (T-37 review): the light of `screen` is clipped to the tube's visible area (`tube_visible_height_mm` x `tube_aspect`) with rounded corners, `geometry_opening_corner_radius_mm` (default 0, square; CRT.md 15 to 40 mm on older tubes): exactly 0 outside, antialiased over one host pixel along a curved outline. Not implemented and deferred (QUESTIONS PHY-11): S-linearity residuals (CRT.md has no residual profile) and refraction through the faceplate (no outer radius or glass thickness per curved tube).
- Faceplate optics (`optics` slot, `shaders/optics*.comp`, `params/optics.toml`, oracle `crt_model::optics`, T-44 and T-45; CRT.md rule 7, QUESTIONS PHY-10), off by default (`optics_enable`, D-6, D-24: the slot is skipped as an exact identity): phosphor-layer diffusion (`optics_diffusion_weight`, `optics_diffusion_mm`), the halation ring of the faceplate glass with its shape derived from the glass (`optics_glass_thickness_mm`, `optics_glass_index`, `optics_glass_transmission`: edge at 1.747 times the thickness, Fresnel haze inside, absorbed tail) and its amplitude as the fraction of light in the halo (`optics_halation_weight`, 1.5 %), veiling glare proportional to the mean picture level (`optics_glare_weight`), vignette (`optics_vignette_corner`, corner / centre), glass tint (`optics_tint_rgb`), diffuse room-light reflection (`optics_ambient_lux`, `optics_screen_reflectance`, `optics_white_nits`); all redistribute light, so a white field keeps its level. Halo method chosen by a headless cost study (`optics_halo_method`, `optics_halo_taps`): the exact kernel on one pyramid level (error 0.010 % mean, 0.13 % max of white; about 1.1 ms for the whole slot at 1920 x 1080 with every effect on, on a clock-limited GPU); a bloom-like pyramid mix and full-resolution Gaussians stay selectable for comparison. Optics panel in the settings menu (generated from the table). Presets 01 to 09 carry their faceplate thickness, halation weight and (05) transmission, and keep the stage off. Tests: `crt-model` oracle unit tests (ring position, kernel normalisation, Fresnel, FFT convolution, energy, vignette, glare, ambient), stage unit tests, `tests/stage_optics.rs` (identity bit exact, point-source ring and energy, edge, flat white and game-like frames against the oracle, diffusion energy, vignette ratio, glare linear in APL, tint and ambient, FP16 round to nearest) and the ignored cost study.
- Tube ageing (T-42, QUESTIONS PHY-14, `params/ageing.toml`, opt-in, `ageing_enable` off by default: the chain is unchanged bit for bit). Phosphor efficiency loss per colour from the hours of use (`ageing_hours`, `ageing_mean_level`, `ageing_white_cd_m2`), Pfahnl law 1 / (1 + c Q) with Q the charge in reference hours of full white at 350 cd/m2, calibrated on the one sourced point (15 % luminance loss after 20,000 h at 350 cd/m2) with relative colour rates (`ageing_rates_rgb`, default blue twice green, red half: white drifts warm); cathode wear per gun in `gun` (`ageing_cathode_loss_rgb`, `ageing_cutoff_drift_rgb`); spot growth of a worn gun (`ageing_spot_growth`, both beam widths scaled on the CPU so the skirt margin, the warp plan and the headroom readout follow). New chain slot `wear` between `screen` and `phosphor` (`shaders/wear.comp`), skipped as an identity while ageing and burn-in are off. Oracle `crt_model::ageing`.
- Burn-in (T-43, QUESTIONS PHY-14, SCP-6, `params/burnin.toml`, opt-in, `burnin_enable` off by default). This deliberately degrades the picture: static bright parts (a HUD, a letterbox edge, a logo) leave a ghost tinted by the colour that wore. A per-colour wear map of 640 x 480 texels over the tube's visible area (independent of the host resolution) accumulates the beam charge every frame (`shaders/wear_accumulate.comp`, exact area mean per texel, FP32 with compensated summation so real-time increments are not lost), at `burnin_acceleration` tube hours per real hour (1 = real time, 0 typed freezes the map), and lowers the efficiency with the same law as ageing. Saved per tube preset in `%APPDATA%\ultimateCRT\tubes\<preset>.state` (magic, schema version, size, CRC-32, atomic write; a missing, corrupt or other-version file is a new tube with a warning and a `.bak` copy; another size is resampled), every 5 minutes from an asynchronous GPU copy written on a background thread, when the preset changes, and at exit. Menu buttons "Burn in N h now" (`burnin_now_hours`) and "New tube (reset wear)" in the new "Ageing and burn-in" panel; `--reset-burnin` starts a new tube. Oracle `crt_model::burnin`; controller and file format `src/tube_state.rs`. Tests: oracle unit tests (decay curve, calibration, accumulation, per-colour independence, ghost only inside the worn area, resampling), file and controller unit tests, and `tests/stage_ageing.rs` (one GPU program: identity when off, blue x 0.85 at 15 % loss, cathode wear, spot growth 1.2, map and ghost against the oracle, calibration point, real-time increments kept, map frozen at acceleration 0 over 1000 frames, asynchronous snapshot, save and load bit exact, corrupt file).
- Interlace, manual field mode (T-32, QUESTIONS SRC-7, `params/interlace.toml`, oracle `crt_model::interlace`, tests `tests/stage_interlace.rs`; optional, `interlace_mode` off by default and bit-identical when off). A capture carries no field parity, so the user declares it: `alternate_frames_are_fields` (each captured frame is one field, the bottom field lands half a line pitch lower) or `split_woven_frame` (a woven frame: each refresh draws only the even or only the odd rows, at twice the line spacing, at their own positions). `interlace_field_order` (top or bottom field first) and `interlace_field_select` (alternate every output refresh, or lock the top or bottom field for inspection; a locked field of a woven frame is the 240p double-strike look). The field changes the beam raster only (`beam_raster`, all beam paths); the decay between fields comes from phosphor persistence. The field code is compiled behind a specialization constant, so the default pipelines are the progressive ones. The live title and console show a notice when the output refresh does not match the field rate. Panel: Beam and scanlines.
- Output transform (`encode` stage): tube primaries and white to sRGB colour matrix (`output_match_srgb`), soft shoulder (`output_knee`), clip counters (`Renderer::clip_counts`), and a final 1 LSB dither (`output_dither`: off, ordered, noise). `crt-model::output` is the f64 oracle; `crt-model` is now a regular dependency of `ultimatecrt`.

New `output_headroom_mode`: `shoulder` (`output_knee` now 0.6, roll-off reaching panel white exactly at `output_shoulder_white`, 0 = automatic from the headroom readout; no roll-off when the readout is at most 1, so peak-free chains stay exact), `physical` (exposure divided by the readout x (1 + `output_headroom_margin`), nothing clips), `mask_depth` (new `mask_depth` limits the mask contrast, mean kept, NON-PHYSICAL; exposure then derived) and `clip` (the previous behaviour). The CPU headroom readout (mask peak x scanline peak x white matrix maximum x exposure; `crt_model::output::Headroom`, `Mask::peak_value`, `beam::scanline_pixel_peak`, `output::shoulder_rate`) is shown through `Renderer::headroom`. Measured: the default shoulder keeps 1 to 4 points LESS of the white mean than the hard clip (it removes clip bands and tints), physical keeps the mean exact at 25 to 69 % of the intended white. The `encode` push constants carry the resolved exposure, knee and rate (72 bytes).
- Curved geometry on the fast beam path (T-91, `shaders/screen_lines.comp`, `shaders/screen_warp.comp`, `shaders/include/beam_warp.glsl`): with a curved faceplate, pincushion, trapezoid or rotation the `standard` beam quality no longer falls back to the `reference` evaluation. The `screen` slot then records two passes: the horizontal profile and spot moments of every raster line at raster columns on a uniform grid (stage-owned line images), then per host pixel its raster position through the geometry, the profile of each line within reach interpolated there (Catmull-Rom) and integrated exactly over the pixel's rows (no vertical resampling, so scanlines do not alias), then the mask, still fixed to the glass, and the visible opening. Within 0.06 % of white mean and 3.7 % max of the exact form on the test patterns (contract 0.5 % and 4 %), flat fields keep their luminance; a curved `screen` now costs 0.35 to 0.39 times a flat one on presets 01 and 05 (it cost 4.7 to 18 times). Flat and separable geometries keep the previous pass bit for bit; a spot under 0.3 host px keeps the exact evaluation.
- Geometry review follow-ups (T-37): the skirt margin is still evaluated but lies outside the visible opening, so it is black and the picture's outer edge no longer moves with the spot size, overscan or `raster_scale`. Overscan and `raster_scale` keep the spot's size and the misconvergence in mm and dim the picture by the raster's area (1 / (sx sy), the same beam current over a larger raster) instead of magnifying the spot with the raster. `screen` takes `raster_scale` 1 when the `abl` slot does not run in the frame (it read a stale or unwritten state before), and the ABL state starts at `apl_f` = `abl_breathing_ref` while the breathing is on, so the first frame has scale exactly 1. The pincushion inverse takes four fixed-point steps (corner residual at |k| = 0.05 from 0.007 to 0.023 mm down to 0.0006 to 0.0028 mm). The standard-vs-reference beam contract is MAE <= 0.5 % and max <= 4 % of white for any pixel alignment (was 2.5 % max, valid only at the identity alignment).

- Release tooling (WP1, R-09, R-17, R-24): `scripts\package.ps1` takes the executables from the target directory that `cargo metadata` reports, runs the tests with `UCRT_REQUIRE_GPU=1`, refuses a dirty tree or an executable older than its sources (`-Force` for a local trial), records `-dirty` and `-untested` in the `.commit` file, and adds `LICENSE`, `BUILD-INFO.txt` (commit, `rustc` and `glslc` versions) and the licence texts of every dependency (`scripts\gen-third-party.ps1`, with a count check) to the zip. `scripts\release.ps1` refuses untested and dirty zips, checks the zip contents, the lock file, the dated changelog heading and the tag against the workspace version, and ends the release notes with the SHA-256 of the zip.

- Behaviour changes of the review pass (WP2 to WP5 and their integration): Esc no longer closes or quits the output window (Ctrl+Alt+Q and the close button quit); the quit hotkey and the close button hide the window and end the loop, and the window is destroyed after the renderer (WP2, R-52, R-16); the `--log` CSV column 14 `fg_title` (the foreground window's title) becomes `fg_exe` (its executable name) (WP2, R-34); the Vulkan loader is looked up in the system folder only (WP2, R-48); a value typed into a slider with Ctrl+click is clamped to the slider range, while a file value (preset, `settings.toml`, `render --set`) outside the new hard range of its parameter is clamped into it with a warning naming the file and the key, and a non-finite one is ignored (WP4, R-05; the settings overrides applied at a new source now take the same path, integration); phosphor persistence follows the real time between frames by default (`phosphor_frame_rate_hz = 0`, automatic rate, frame steps clamped to 250 ms) instead of a fixed 1/60 s per output frame, so on a display that is not at 60 Hz the trail now lasts the same time as at 60 Hz and no longer as before (2.4 times longer than before at 144 Hz, shorter below 60 Hz); a positive value restores the fixed per-frame period (WP5, R-11); the amp oversampling is capped in every quality tier by the device's largest image side and a per-image memory budget (256 MiB, less on a GPU with under 4 GiB), with a notice in the console and the window title (WP3, R-02); device selection is stricter: a GPU without a graphics and compute queue family, `fragmentStoresAndAtomics`, 256 compute invocations per workgroup or 28 KiB of compute shared memory is refused at start, with the missing item named (WP3, R-29); a lost GPU (driver reset or update, or a GPU that does not answer within 5 s) ends the session after the saves with a plain message instead of an error code (WP3, integration).

### Fixed
- The `encode` pass cost up to 3.5 ms at 1920 x 1080 (4.6 ms at 2560 x 1440) on detailed content (1-px checker, noise, game art with highlights) against 0.1 ms on flat content (T-47, T-93: "cause not found"): the clip counters were incremented with atomics on a host-visible storage buffer, so every clipping pixel sent an atomic across the bus. The counters are now in device-local memory, cleared on the GPU and copied to the host after the pass: `encode` costs 0.04 to 0.25 ms on every content. Measured by isolation: the shader without the atomics took 0.13 ms on the checker; a per-subgroup reduction of the counts in host memory did not help (the driver already merges a warp's atomics), the memory move alone did.
- Picture area Auto still found no bars on a real capture (second owner live test 2026-11-20; QUESTIONS CAP-7, ARCHITECTURE A26): the rounded bottom corners of the Windows 11 window are captured with the client area, and their grey anti-aliased pixels made the bottom row and the outermost columns count as picture, so only the top bar was found (on the owner's 1100 x 800 capture of pixel-demo: bars 0, 288, 0, 0 instead of 422, 288, 422, 288). The detector now leaves a 48 px square at each frame corner out (at most 15 % of an axis), and a row or column is picture only with at least 2 lit pixels and 0.5 % of its length, so a hot pixel or a 1 px cursor is ignored too. The real frame is a test fixture (`crates/ultimatecrt/tests/data/capture-1to1-1100x800.png`) with regression tests on it and on synthetic corner artefacts (strength 14 to 60, 100 % and 125 % zone sizes), cursor and hot pixels, noisy edge lines, pixel-demo at x3, pictures touching the window edges, a dark scene, black frames with corners, and thin lines of content.
- Stored manual picture-area limits made for another window size were applied anyway and kept Auto off without saying so (the owner's pixel-demo profile held a crop from a 1920 x 1027 window): they are now not applied when the captured client size differs from the one stored with them; the picture area is detected instead, the Source section shows "Manual (stored)" with both sizes and Back to Auto, and the console says so at attach.
- Black-bar detection did not crop a small game in a large window (owner live test 2026-11-20: pixel-demo 256 x 224 at x1 centred in a 914 x 754 client area; QUESTIONS CAP-7): the guard rail refused to remove more than 60 % of an axis, and the bars removed 72 % of the width and 70 % of the height. The guard now allows up to 97 % (`[global.source] bars_largest_crop`, 10 to 99 %) and adds a minimum picture of 16 source pixels and 2 % of the axis, so an almost black capture never collapses to a sliver; a blocked axis is reported in the Source message with its reason ("the bars would remove 99 % of the width, more than Largest crop allows") instead of a silent no-op. The old keys `bars_max_crop` (whose stored 0.6 would have kept the bug) and `detect_bars_at_attach` are dropped when the settings are read. The frame on screen at start now counts for the detection at attach (a window that does not redraw gave "no picture").
- The presets' 'no clip' exposure notes (T-84): the exposure bounded the unmasked white only; a flat-white chain test per preset (`tests/presets.rs`, every headroom mode) now checks the output against the oracle, that the headroom readout bounds the brightest element, and that the physical and mask depth modes clip nothing.
- FP16 stage stores round to nearest, ties to even, on every device (`round_f16` in `shaders/include/common.glsl`, applied at every `imageStore` of `decode`, `resample`, `amp`, `gun`, `abl` and `screen`): the Vulkan spec leaves the float to FP16 rounding to the implementation and this NVIDIA driver truncated (bias -2^-10 to 0 per store, about -0.15 to -0.2 % after the chain). The 8-bit identity budget drops from 0.4968 to 0.311 of a code on an RGBA16F target (0.186 on an 8-bit target), the stage tests use the symmetric half-ulp window, and `gpu_fp16_store` checks the stores bit for bit against a CPU reference.
- The Esc hint is no longer printed for a `--no-activate` output.
- `pixel-demo` handles `WM_DPICHANGED`: a window dragged to a monitor with another scaling no longer loses client area (live-A); an exact-size window stays exact, otherwise Windows' suggested rectangle is used. The animation clock no longer depends on the 8 ms `WM_TIMER` (about 57 distinct frames per second).
- `pixel-demo` integer scale taller or wider than the work area (live run 2026-11-19: from x5 on a 1080-line monitor Windows capped the client height at about 1181 while the title still said `integer xN`, so the picture was clipped): the initial window and the digit, M and N keys now clamp the integer scale to the largest one whose exact window (frame included, at the window's DPI) fits the work area of its monitor and move the window back inside it; the title never claims an undisplayed scale (`integer x5 (clamped to x4)`) and the console reports the clamp. An explicit `--window` size, maximised and fullscreen are left alone. Pure functions `clamp_integer_scale`, `max_client`, `integer_label` and `shift_into` in `layout.rs` with unit tests (1920x1080, 1920x1200, 2560x1440, DPI 100, 125 and 150 %, PAR, bounds).
- `scripts\check-menu.ps1` reported FAIL although the menu worked (live run 2026-11-19: 19 foreground changes instead of 20 windowed, because the output already had the foreground before the first open; 20 instead of 22 fullscreen, because the startup hand-back happens before the poll starts). The pass criterion no longer counts the total changes: the pure function `Test-MenuForeground` judges each cycle against the independent poll (menu open: the output has the foreground within the settle time and keeps it; menu closed: the source has it, T-07 blips of at most 1 s apart; another window or a long output hold fails) and reports the startup state as a note. New `-SelfTest` mode runs it on recorded sequences (the two false FAILs, a correct run, a run with a blip, six broken runs).
- The default windowed output no longer takes the foreground and the keyboard focus at start (OUT-2, live run 2026-11-19): every output mode is now non-activating (`WS_EX_NOACTIVATE`, `SW_SHOWNOACTIVATE`, T-07 hand-back), except while the settings menu is open and after a drop to a window when the source is lost. Moving or resizing the framed output by its title bar or frame is done by the output itself (no Windows modal move loop, which activated the window), so a click or a drag leaves the foreground and the keyboard on the captured window; Aero snap does not apply to it. `--no-activate` is still accepted and has no effect; Esc no longer closes a windowed output (Ctrl+Alt+Q quits).
- `pixel-demo` no longer stops painting after a bare Alt (or F10) press (CAP-4 stall of 2026-11-19): the keyboard menu mode of `DefWindowProc` ran a modal loop that blocked the frame timer loop until the next key or click, so a capture got one frame and then none. `WM_SYSCOMMAND` `SC_KEYMENU` without a character is now ignored (Alt+Space still opens the window menu).

### Security

- Review pass before the public v0.2.0 (a three-reviewer code review, reconciled into 71 items; `R-nn` are the ids of the reconciled report, `WP1` to `WP5` its work packages). Security and privacy items:
  - R-48 (WP2): the Vulkan loader is no longer looked up in the application folder first (`SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)` is the first call of `main`), so a `vulkan-1.dll` placed next to an unzipped release cannot be loaded (DLL planting).
  - R-34 (WP2, WP1): `--log` no longer records the title of the foreground window (the `fg_title` column is replaced by `fg_exe`, the executable name; `fg_pid` and `fg_is_source` stay). `settings.toml` still stores the title of the last captured window, which is now documented in the README privacy note, and the output of `poll-foreground.ps1` is git-ignored.
  - R-07, R-08 (WP1): the project has a licence, MIT (`LICENSE`, `license = "MIT"` in the workspace and every crate), and the release zip carries the licence texts of every dependency and the notices of the bundled C++ code and fonts instead of a table of SPDX names.
  - R-56 (WP1): the licence gate refuses GPL, LGPL and AGPL, also in an `OR` expression, unless `deny.toml` allows the licence; `package.ps1` and `check.ps1` apply it and run `cargo deny` when installed.
  - R-03 (release step, not a code change): the author e-mail address is removed from every commit by a one-time history rewrite before v0.2.0 is published, the one exception to the "no force pushes to `main`" rule (DESIGN 11, ENV 7).
