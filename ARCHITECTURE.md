# ARCHITECTURE

How ultimateCRT is built and why. The need is in `CLAUDE.md`, the physics in `CRT.md`, the open questions and decisions in `QUESTIONS.md` (ids such as SRC-2 refer to it). Coding rules are in `DESIGN.md`, build and release in `ENV.md`.

Status legend: **Implemented** means it is in the code today. **Planned** means it is decided or defaulted in `QUESTIONS.md` but not written.

## 1. Context

ultimateCRT runs next to the program it enhances. It never injects into it, hooks it or sends it input.

```
 source program (any window)            ultimatecrt (this project)
 ┌───────────────────┐   Windows.Graphics.Capture   ┌────────────────────────────────────────────┐
 │ game / emulator   │ ───────────────────────────► │ capture ─► scaling ─► Vulkan passes ─► out │
 │ (pixel art, 1:1)  │   GPU texture of the window  │  (CPU copy)  (÷N)      (GLSL)     window   │
 └───────────────────┘                              └────────────────────────────────────────────┘
                                                      output window: borderless, topmost, never takes focus
```

Constraints: Windows 11 x64 only, SDR output, a Vulkan 1.3 GPU (developed on an NVIDIA RTX A2000 Laptop, a hybrid-graphics machine with an Intel iGPU). One screen must work: the fullscreen output covers its own source.

### 3.2 Per-frame data flow (Implemented)

1. **Capture thread** (thread-pool thread of the free-threaded frame pool). `Worker::on_frame` receives the frame texture, computes the client area inside it (`DwmGetWindowAttribute(EXTENDED_FRAME_BOUNDS)` against `ClientToScreen`), copies that region into a staging texture, maps it and copies the rows into `Shared.frame` (a `Mutex<Frame>`), incrementing a sequence number. If the content size changed, it recreates the frame pool.
2. **Main thread** pumps Win32 messages, then `take_frame` swaps the newest frame's buffer into the renderer's `Frame` (latest frame wins, no queue, no allocation once sizes are stable).
3. `scaling::Detector::feed` analyses the frame until its divisor is locked (30 informative frames, or earlier when the source is native). A flat frame, such as a black boot screen, is not informative and does not count. The result and the optional `--crop` form a `View`.
4. `Renderer::render` waits for its frame slot, copies a new frame into the slot's persistently mapped staging buffer, and records the `Pipeline` (3.7): buffer-to-image copy into the `B8G8R8A8_UNORM` source image, `decode`, the chain slots (3.7), `encode` into the swapchain image, then the UI pass when the settings menu or the overlay is shown (3.8).
5. `decode.comp` fetches the texel at `origin + p * div + div / 2` for native pixel `p` (the centre of each block), so no separate downscale pass exists.
6. Present with FIFO (vsync). The swapchain is `B8G8R8A8_UNORM`: `encode` writes display code values, encoded explicitly with the host EOTF.

### 3.3 Threading and synchronisation

- Two threads touch frames: the capture callback (producer) and the main loop (consumer). They share only `Shared`: a `Mutex<Frame>`, an `AtomicBool` for the closed-window event and an `AtomicU64` frame counter.
- The Direct3D device is created with multithread protection. The immediate context is used only inside the callback, inside `Worker`, which is moved there (`unsafe impl Send` with that invariant).
- Vulkan is used from the main thread only. There are two frames in flight (3.7): per frame slot one fence, one command buffer, one image-available semaphore; one render-finished semaphore per swapchain image. The swapchain is rebuilt on size change or `OUT_OF_DATE`.

### 3.4 Output window (Implemented)

Raw Win32, not winit, because the behaviour needed (non-activating, topmost, tool window, `MA_NOACTIVATE`, global hotkey, per-monitor DPI v2) is Win32 specific.
- Fullscreen: `WS_POPUP` with `WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`, shown with `SW_SHOWNOACTIVATE` over the monitor of the source window (or `--monitor`). It never takes the keyboard focus.
- Focus hand-back (T-07): the styles do not stop a foreground switch that Windows (or a resident program, not identified) makes about 25 s after the process starts, with or without Vulkan (QUESTIONS OUT-2). A non-activating output (every mode, the default windowed one included since 2026-11-19, OUT-2) answers `WM_ACTIVATE` without `DefWindowProc` and hands the foreground back with `SetForegroundWindow`: to the window the activation came from, else the last other foreground window (sampled by `output::pump`), else the source window. The decision is the pure `output::hand_back_target` (unit tested). What remains is a foreground blip of about 0.1 s; the keyboard focus stays on the source. `scripts/check-focus.ps1` is the live regression check (PASS, MITIGATED for hand-backs only, FAIL).
- Windowed: overlapped window with `WS_EX_NOACTIVATE` (OUT-2). A left press on the title bar or the frame (`WM_NCLBUTTONDOWN` with `HTCAPTION` or an edge or corner code) starts a move or resize that the output runs itself (`SetCapture`, `SetWindowPos` with `SWP_NOACTIVATE`, pure `output::drag_rect`), because Windows' modal move loop activates the window and gives it the keyboard focus whatever its styles; Aero snap therefore does not apply. A move loop entered another way defers the hand-back to `WM_EXITSIZEMOVE` (`output::on_activate`). Esc closes only an activating window from `output::drop_to_windowed` (no longer used by the app since A23: a lost source given up turns a fullscreen output into the non-activating framed window and shows the picker); with the settings menu open Esc closes the menu, in the picker it clears the search or cancels (3.9).
- Hotkeys (T-54, PLAN D-17, QUESTIONS OUT-5): `RegisterHotKey` only, no keyboard hook. `hotkeys::plan_registration` lists, per action, the wanted chord then a short fallback list; `register_all` tries them through the `Registrar` trait (`output::Win32Registrar` on the output window, a fake in the unit tests), and returns a `Registration` (chord in force per action, one message per failure naming the chord and the Win32 error, `has_problems()` as the flag the UI shows; kept in `Output::hotkeys`). The `RegisterHotKey` id is the action's discriminant plus one (Quit is 1, as before). `WM_HOTKEY` maps the id to an `Action` and pushes it on a queue (`output::take_actions`); Quit also destroys the window at once so it works with a busy loop. The loop drains the queue once per iteration (`live::Live::tick`): `controls::dispatch` changes `Controls` or calls the `UiHook` (menu, overlay) or returns a `Command` (`SetBypass`, `StepPreset`, `ToggleWindowMode`) that `live.rs` applies. The keys still arrive as `WM_HOTKEY` while the menu has the focus, so the menu key closes it. Default chords and the fallback lists: `hotkeys.rs` (documented in the README). A fullscreen output refuses to start without Ctrl+Alt+Q (it has no keyboard exit); a windowed one warns. `Output` unregisters every chord and destroys its window in `Drop`. A global hotkey is swallowed for every program, so a captured game loses F11 and F10 while ultimatecrt runs (configurable).
- Output modes (T-57, QUESTIONS OUT-1, OUT-5): F11 runs `modes::ModeState::toggle` (pure, unit tested) and `output::apply_placement` applies the result: borderless `WS_POPUP`, topmost, tool window over the monitor the window is on, or `WS_OVERLAPPEDWINDOW`, not topmost, at the remembered outer rectangle (`settings.global.output.windowed`, used only when at least half of it is on a monitor, else the default size centred). The window is hidden during the style change so the taskbar updates, except while it holds the foreground (menu open). Never `SWP_ACTIVATE`. Both modes are `WS_EX_NOACTIVATE` unless the settings menu is open: `apply_placement` only records that the mode wants a non-activating window, and `output::sync_activation` (the one place that writes `WS_EX_NOACTIVATE` and the flag the T-07 hand-back reads) combines it with the menu state (`effective_no_activate`, pure, unit tested). F11 therefore works with the menu open (the menu stays usable and keeps the focus) and closing the menu afterwards restores the behaviour of the new mode. `WM_DISPLAYCHANGE` raises a flag; the loop asks `ModeState::display_change` for a new placement (fullscreen: the monitor holding most of the old rectangle; framed: only when mostly off screen). `WM_DPICHANGED` applies the suggested rectangle in the framed mode. The swapchain follows the client size (`Renderer::render` recreates it through `Presenter::resize`); the picture is placed by `placement.rs` (letterboxed). `lifecycle::LostWatch::set_fullscreen` keeps the lost-source drop (T-56, `output::drop_to_windowed`) in step with F11.
- Cursor (CAP-6): `WM_SETCURSOR` answers with no cursor over the client area while `output::set_cursor_hidden(true)`, which the loop sets to `!ui.wants_input()`. The captured cursor stays off. Click-through (D-8, OUT-4): not implemented (no command-line flag yet); the plan is `WS_EX_LAYERED | WS_EX_TRANSPARENT` toggled with the style functions above.
- Settings menu (T-52a, D-7): the menu hotkey (default F10, fallbacks Ctrl+Alt+F10, Ctrl+Alt+F12) reaches `ui::Ui::request_toggle` through `controls::UiHook`, the overlay hotkey (Ctrl+Alt+O) `Ui::toggle_overlay`. `output::set_menu_open` switches the menu mode. Open: `sync_activation` makes the output activating, which also switches the T-07 hand-back off (`hand_back_target` answers `None` for an activating output), so the menu's own activation is never undone; the routed input messages (`ui::input::routed`: mouse, wheel, keys, characters, focus, activation, DPI) are queued for the UI (`take_ui_messages`) and the consumed ones (`ui::input::consumes`) are answered without `DefWindowProc`; Esc closes the menu and gives the foreground back (`ui::menu::closes_on_key`), it never closes the output while the menu is open; the mouse is captured while a button is down; `WM_SETCURSOR` over the client area shows ImGui's cursor (`set_menu_cursor`). The other hotkeys (F11, the presets, the bypass, Ctrl+Alt+Q) are `WM_HOTKEY` registrations and keep working with the menu open. Close: queueing stops, the capture is released, the activation behaviour of the current mode comes back (`sync_activation`; after `drop_to_windowed` the framed window stays activating). `WM_DPICHANGED` is queued in both modes. The menu shows the hotkey registration problems (`Registration::problems`) under its key hint.

### 3.5 Device choice (HW-3 policy implemented, checked live 2026-11-19)

One adapter runs the whole chain: the capture's Direct3D 11 device and the Vulkan renderer are created on the same adapter, named by its LUID (owner decision 2026-11-19, D-18: adaptive to any host).
- **Request:** `--gpu <index>` (Vulkan index) wins over the setting `[global.gpu] adapter` in `settings.toml`: `auto` (default), an adapter LUID (`00000000:00017801`, as `--list-adapters` prints it) or a case-insensitive part of the DXGI or Vulkan adapter name. Read at start only; changing it needs a restart.
- **`auto`:** the DXGI adapter whose attached output overlaps the output window rectangle the most (`adapters::owner_of_rect`), matched to the Vulkan device with the same `deviceLUID`. When that is unknown, or that adapter has no usable Vulkan device, the previous default: an NVIDIA discrete GPU, else any discrete GPU, else the first Vulkan 1.3 device with a graphics queue.
- **Decision:** `adapters::select` (pure, unit tested on the dev machine topology) returns a `GpuSelection { chosen, reason, owner, warnings }`. A request that matches no usable device warns and falls back to `auto`; an ambiguous name takes the first match and warns; a chosen adapter that is not the one driving the covered monitor warns (each presented frame crosses adapters). `adapters::Topology::read` gathers the inputs (DXGI enumeration, query-only Vulkan instance); `adapters::publish` and `adapters::current` keep the selection and the adapter list (`AdapterEntry`: name, LUID, owns monitors, Vulkan index, setting value) for the settings menu.
- **Order at start (`app.rs`):** the output window does not exist when the capture starts (its size comes from the first frame), so the capture device is created on a first guess from where the output will go (fullscreen: `--monitor` or the source's monitor; windowed: the remembered rectangle). Once the window exists, the selection is made again from its real rectangle, the renderer asks for that LUID (`gpu::DeviceRequest::Luid`; a device that cannot present to the window falls back to the default with a warning), and the capture session is restarted on the renderer's adapter if the guess differed. Reattached sessions (T-56) use the same adapter. The console prints `gpu: <adapter> (Vulkan [i], LUID ...; <reason>)` and one `warning: gpu: ...` line per warning.
- **Capture device:** `capture::create_device` finds the adapter with `IDXGIFactory1::EnumAdapters1` by LUID and calls `D3D11CreateDevice` with it (`D3D_DRIVER_TYPE_UNKNOWN`); without a LUID, the default adapter as before.
- **Not handled:** moving the output to a monitor of another adapter after start (F11, a drag) does not re-select or re-warn; the selection holds for the session.
- **Live check (2026-11-19, covered pixel-demo, fullscreen, QUESTIONS HW-3).** `auto` chose the RTX on the RTX-driven monitor and the Intel UHD on the Intel-driven monitor; `[global.gpu] adapter` and `--gpu` overrode it and printed the cross-adapter warning. Medians, in this order: RTX on its own monitor, capture 57.4 fps, render 60.4 fps, GPU 2.82 ms (one earlier run had its capture stalled at 0 fps, cause unknown); Intel on its own monitor, capture 40.4 fps, render 51.5 fps, GPU 15.45 ms; RTX presenting on the Intel monitor, capture 58.6 to 59.2 fps, render 60.6 fps, GPU 2.5 to 3.0 ms; Intel presenting on the RTX monitor, capture 42.3 fps, render 60.1 fps, GPU 12.35 ms. No crash in any case.

### 3.6 Parameter table (Implemented; `exposure` is read by `encode`)

Every CRT parameter is defined once (DESIGN section 8), in `params/<stage>.toml`: id, stage, type (f32, i32, bool, enum, vec2, vec3, vec4), unit, default, soft range, confidence tag (S, D, K, E), source, description, UI group, enum values. One file per stage, so stage tasks do not edit the same file. The format is documented in `crates/paramgen/src/lib.rs`.

`build.rs` calls `crates/paramgen` (a build dependency, `serde` and `toml`), which validates the files and writes to `OUT_DIR`:
- `params.rs`, included by `src/params.rs`: the `Params` struct with the table defaults, `PARAMS_META` (all metadata, for the UI, presets and documentation), `write_std140` and `to_std140` (the uniform buffer bytes), `get` and `set` by id, one `u32` constant per enum value;
- `params.glsl`: the same constants and a `Params` uniform block (instance `params`, set and binding 0 unless `UCRT_PARAMS_SET` and `UCRT_PARAMS_BINDING` are defined) whose members carry explicit `layout(offset = N)`. `build.rs` compiles a shader that includes it with `glslc`.

The std140 layout is computed once, in declaration order (production files sorted by name), and written into both outputs. Parameters live in a uniform buffer, not push constants (128 bytes minimum limit). A duplicate id, an out-of-range default, an unknown key or a missing field fails the build with a message naming the file and the id. Test-only entries (`params/_test.toml`, every type) are placed after the production entries and exist only in non-release builds (`cfg(ucrt_test_params)`). Stage-specific ids are added by their stage tasks; today there is one file per built stage: `output.toml` (`exposure`, matrix, shoulder, dither), `colour.toml` (tube primaries and white in CIE xy), `source.toml` (`source_eotf`, `raster_aspect`, `source_par`, `line_multiplier`), `tube.toml` (visible height, aspect, height fraction), `amp.toml`, `gun.toml`, `abl.toml`, `beam.toml` (spot, `beam_quality`), `geometry.toml`, `mask.toml`, `phosphor.toml` (saturation and persistence), `optics.toml` (T-45), `ageing.toml` and `burnin.toml` (T-42, T-43), `composite.toml` (T-31, read by the `signal` slot).

### 3.7 Pipeline core (Implemented, T-20a; stage slots and image contract T-20b)

`gpu/pipeline.rs` owns the fixed ordered chain of stages (A11, TEC-6), the images between them and the frames in flight. The window `Renderer` and the headless renderer run the same `Pipeline`.

Chain: upload (captured BGRA8 to the `src` image) -> `decode` (compute) -> the chain slots `signal` -> `amp` -> `gun` -> `abl` -> `screen` -> `wear` -> `phosphor` -> `optics` (registry `stages::CHAIN`, one registration line per slot) -> `encode` (fragment) -> target (swapchain image or headless image).

**Image contract** (T-20b). Every chain image is `R16G16B16A16_SFLOAT`. Three domains, with sizes from `FrameConstants`:

| Domain | Size | Content |
|---|---|---|
| native | `native_size` (source pixels after crop and divisor) | drive voltage (code value) per channel, voltage domain |
| amp | `native_size * (K, 1)`, K = `FrameConstants::amp_k`, default 4 (`AMP_K`) | native rows supersampled horizontally by K: drive voltage (`amp` output), then beam current (`gun` output) |
| tube | `tube_size` = the tube rectangle in host pixels (corners are whole pixels) | linear light per host pixel |

| Stage | Kind | Reads | Writes | Today |
|---|---|---|---|---|
| `decode` | compute | `src` (`B8G8R8A8_UNORM`, capture size), at block centres `origin + p * div + div / 2` of the `View` | `native`: the drive voltage V in [0, 1] (`drive_voltage`: `code / 255`; `srgb`: `srgb_eotf(code / 255)^(1 / gun_gamma)`); with a non-identity `Settings::source` (test hook, default identity) the stand-in transfer is applied on top | T-20a; T-30 `source_eotf`; T-34 (the tube gamma moved to `gun`) |
| `signal` | slot, native -> native | `native` | its own native image | composite video module (T-31, `stages/composite.rs`, `shaders/composite.comp`, `params/composite.toml`, oracle `crt_model::composite`): optional NTSC or PAL composite or S-Video encode, channel, luma/chroma separation and decode in the voltage domain, see "Composite video" below; `composite_enable` off (default) = skipped as an identity (no pass) |
| `amp` | slot, native -> amp | `signal` output | its own amp image | video amplifier (T-33, `shaders/amp.comp`, `params/amp.toml`): Gaussian low-pass of the drive voltage on the K-times oversampled line, each sub-sample the exact box integral (mean) of the continuous output over its interval; asymmetric rise/fall (slower edge delayed, smear trails right); optional peaking; black blanking outside the active line; output clamped to the local input range (slew limiter, widened by the peaking overshoot); ideal (exact hold) when every edge sigma is at most 0.01 source px (the defaults); bypass = zero-order hold |
| `gun` | slot, amp -> amp | `amp` output (V) | its own amp image (not in place): beam current per channel, 1 at full drive; a disabled slot passes V through bit for bit, and `encode` then treats V as linear light, so the picture is lighter than with the gun on (code 20 shows about code 80 instead of 20 on a pure 2.2 host), not darker | `gun.comp` (T-34): law `gun_law` = power / gog / bt1886 / bt1886_annex1 of `params/gun.toml` (laws in `shaders/include/gun_law.glsl`, shared with `decode`, whose `srgb` mode inverts the nominal curve of the active law; `gun_gamma` clamped to >= 0.1), times `FrameConstants::white_gain` (white retune, relative to the tube white, solved on the CPU by `src/white.rs` from the primaries and white xy of `colour.toml` and the target `gun_retune_white_xy`, only when `gun_white_balance` is on, default off; (1, 1, 1) when the target is the tube white); `gun_bt1886_white` matters only through Lb / Lw; oracle `crt_model::gun` |
| `abl` | slot, amp -> amp | `gun` output (beam current) | its own amp image: current x g(apl_f) | `abl.comp` + `reduce.comp` (T-35), see "ABL and raster breathing" below; off by default (`abl_enable`); with the limiter, the breathing and the probe all off the slot is skipped as an identity (no pass) |
| `screen` | slot, amp -> tube | `abl` output | its own tube image: `mask_eval(q) * beam_eval(gun, q)` per host pixel q | `screen.comp` (T-36a, T-36b, T-36c, T-37, T-39a to T-39c): product `mask_eval(q) * beam_eval(gun, q)` per host pixel, see the bullets below. `beam_eval`: scanline profile vertically and the round spot with spot growth horizontally, `beam_quality` `standard` (separable per workgroup tile, the default) or `reference` (exact 2D sum); the geometry hooks `geometry_footprint` and `geometry_convergence_px` and `raster_scale` from the ABL state; under a non-separable geometry (curved faceplate, pincushion, trapezoid, rotation) the standard quality records the two-pass warp path instead (T-91: `screen_lines.comp` into the stage's line images, then `screen_warp.comp` per host pixel with the same mask and opening; see "Warp path" below). `mask_eval`: aperture grille, slot mask or delta dot (`mask_type`), exact area mean per host pixel with per-axis tiers (integrated, blend band, prefiltered; `FrameConstants::mask_box_px` decided on the CPU), lattices centred on the tube centre, optional damper wires. The tube image carries a skirt margin. Without a placed tube (px per mm 0) it is the nearest amp sample and mask 1.0 (identity tests) |
| `wear` | slot, tube -> tube | `screen` output | its own tube image; owns the two RGBA32F burn-in map images (640 x 480) | ageing and burn-in (T-42, T-43, `wear.comp`, `wear_accumulate.comp`), see "Ageing and burn-in" below; ageing without hours and burn-in off (default) = skipped as an identity (no pass) |
| `phosphor` | slot, tube -> tube | `wear` output | its own tube image; owns three RGBA32F history images | saturation (T-40, `saturation.comp`, `include/saturation.glsl`: L = I / (1 + s I) per channel, `phosphor_saturation`) and persistence (T-41, `phosphor.comp`, `params/phosphor.toml`, saturation applied before the history), see below; persistence and saturation both off (default) = skipped as an identity (no pass) |
| `optics` | slot, tube -> tube | `phosphor` output | its own tube image; owns its pyramid levels, kernel halo, diffusion image and weight buffer | faceplate optics (T-45, `optics*.comp`, `include/optics.glsl`, `params/optics.toml`, oracle `crt_model::optics`): phosphor-layer diffusion, halation ring (kernel method), veiling glare, vignette, glass tint, ambient reflection, see "Faceplate optics" below; `optics_enable` off (default), an unplaced tube or every effect neutral = skipped as an identity (no pass) |
| `encode` | fragment, one triangle over the target | the last tube image, texel `floor(frag) - tube_rect.xy` | target: inside the tube rectangle the output transform (T-46, below); outside, the surround colour `source_surround_color` (clear colour; the draw is scissored to the tube rectangle, T-96) | T-20a; T-46 |

- **Output transform** (T-46, `shaders/encode.frag`, `include/output.glsl`, oracle `crt-model::output`). Per fragment of the tube rectangle: exposure (`exposure`), then the 3x3 colour matrix `inv(M_sRGB) M_tube` in linear light (pushed as three rows; built on the CPU by `stages::encode::output_matrix` from `tube_*_xy` with `crt_model::output::tube_to_display`; identity with `output_match_srgb`, which is on by default so that the default chain stays an exact identity until the presets (T-50) choose per tube; a degenerate tube falls back to the identity), clip counters, the soft shoulder per channel (`output_knee`: identity up to the knee, then `k + (1 - k)(1 - exp(-(x - k)/(1 - k)))`; knee 1 is a hard clip; negatives clip to 0), the inverse host transfer (`Settings.host`, default pure 2.2, piecewise sRGB optional, COL-3; moving it into the parameter table is left for the settings tasks, because the identity tests use `Transfer::Identity`), then the dither (`output_dither`: off, ordered 8x8 Bayer, or interleaved gradient noise that moves with the frame index; code = `floor(v * levels + threshold)`, so the error is below 1 code and unbiased; `levels` follows the target format, 255 for 8-bit, 1023 for 10-bit, none for float targets, which are never dithered). Clip counters (`over_white`: a channel above 1 after exposure and matrix; `out_of_gamut`: a channel below 0) are counted with atomics in a per-frame-slot storage buffer (`fragmentStoresAndAtomics`) in device-local memory (`headless::DeviceBuffer`), cleared by `vkCmdFillBuffer` before the draw and copied after it into a host-visible buffer, which the CPU reads after the slot's fence (`Renderer::clip_counts`, one frame-in-flight old; `Rendered::clip` in headless). Until 2026-11-20 the counters were in the host-visible buffer itself, so every atomic crossed the bus: that was the unexplained content-dependent `encode` cost of T-47 (see "Performance work 2026-11-20"). A tube white that is not D65 is a per-channel gain (Y = 1): its blue (9300 K) can exceed panel white, which the counter shows; there is no hidden normalisation (COL-1). **SDR headroom (T-84, D-16):** a full-white field is not flat (the mask normalises by coverage, a resolved stripe reads about 1 / fill; scanlines peak above their mean), so the CPU computes per frame a headroom readout (`src/headroom.rs`, oracles `crt_model::output::Headroom`, `Mask::peak_value`, `beam::scanline_pixel_peak`): mask peak (the frame's own per-axis tier decision, 1 when prefiltered, off or `screen` not running) x scanline peak (host-row mean at the full-drive spot width) x white matrix maximum (row sums of `M g`, positive parts when the mask or the scanlines separate the channels) x exposure, an upper bound of the brightest output element (checked per preset by the flat-white chain test of `tests/presets.rs`). `output_headroom_mode` selects what `encode` does with it, resolved on the CPU into push constants (`headroom::OutputTransform`: exposure, knee, rate). The default is `auto` (T-84b, owner decision 2026-11-19 "default to C" made adaptive to the host, D-18): `headroom::effective_mode` resolves it every frame to `mask_depth` when the readout's physical mask peak is above 1 (a resolved mask exists) and to `shoulder` otherwise (the peak comes from the scanlines only, nothing for a depth limit to lower); the pipeline uploads the resolved mode in the `Params` buffer, so the shaders never see `auto`. The modes: `shoulder` (exposure unchanged, above `output_knee` (0.6) the curve `k + (1 - k) min((1 - exp(-a t)) / a, 1)`, t = (x - k) / (1 - k), whose rate a makes it reach panel white exactly at the white point `output_shoulder_white`, 0 = readout x (1 + `output_headroom_margin`); a readout <= 1 leaves the identity, so chains without peaks stay exact; rate 1 is the T-46 asymptotic shoulder), `physical` (exposure / max(1, readout (1 + margin)), hard clip that nothing reaches), `mask_depth` (NON-PHYSICAL: `mask_eval` returns mix(1, m, `mask_depth`), mean kept, then the exposure as in physical from the lowered readout) and `clip` (T-46 hard clip). The clip counters count before the shoulder in every mode. The readout is exposed by `Renderer::headroom` (UI) and `Headless::last_headroom`. Measured on 2560 x 1440 (320 x 240 source): readouts 1.41 to 3.87; the shoulder keeps 45 to 84 % of the white mean, 1 to 4 points less than the hard clip (it removes the clip bands and tints, not the mean loss); physical keeps the mean exact at 25 to 69 % of the intended white. Default `auto` on the same host (share of the intended white kept; `tests/presets.rs` asserts at least 85 % or a documented per-preset floor): the six presets without a resolved mask (01, 02, 04, 07, 09, 10) run the shoulder and keep 72 to 84 %, the four with a resolved mask (03, 05, 06, 08; mask peak 2.96 to 3.85) run `mask_depth` at their own `mask_depth` 0.25 and keep 57 to 63 % (the parameter default 0.5 would keep 40 to 47 %; the readout gives a depth of about 0.05 for 85 %, a nearly flat mask). With the derived exposure the white kept is 1 / (readout x 1.02), so no single depth fits every tube: it is a per-preset setting. The presenter records whether a 10-bit SDR format is offered (`Presenter::ten_bit_offered`); the swapchain stays `B8G8R8A8_UNORM`.
- **Transfers** (`Transfer`: identity, pure power, piecewise sRGB) are named functions in `shaders/include/common.glsl` (DESIGN 8). Defaults (`Settings`): `source` = identity, `host` = power 2.2. T-34 moved the tube gamma out of `decode` (where `Settings::source` stood in for the gun law until then) into the `gun` slot: `decode` writes the drive voltage V (contract documented in `decode.comp`), `gun.comp` applies the law (default pure power 2.4, `params/gun.toml`), and the `srgb` mode of `decode` inverts the power law of `gun_gamma`. `Settings::source` remains as an optional test hook (default identity). The end-to-end default is unchanged; the extra FP16 rounding of V before the law widens the identity error budget from 0.24 to 0.50 of a code (`tests/gpu_identity.rs`). The host transfer moves into the parameter table later (T-46).
- **Slot contract** (`gpu/stages/mod.rs`): a slot is a `Registration` (name, input and output domain, constructor of a `Stage`). A chain stage is a compute pass (`ComputePass`, 8x8 groups) with set 0, binding 0 `Params` (T-10), binding 1 `FrameConstants`, binding 2 its input (combined image sampler, `texelFetch`), binding 3 its output (write-only `rgba16f` storage image of its output domain size). No stage updates an image in place: every slot that runs writes its own image (ping-pong by construction); a stage that needs its previous output (T-41) owns its history images. Settings that are not yet parameters go in a push-constant block. The stage records only its dispatch: images, descriptor sets, routing and barriers belong to the pipeline. `check_chain` refuses a chain whose domains do not connect (first input native, last output tube).
- **Enable flags and bypass:** every slot has an enable flag (on by default; `Renderer::set_stage_enabled`, `Headless::set_stage_enabled`, `Headless::enable_only`). A slot that is off, or whose stage is a placeholder, is an exact identity: a same-domain slot is skipped (the next slot reads the same image, nothing recorded), a domain-changing slot (`amp`, `screen`) runs `shaders/resample.comp`, a nearest-neighbour copy of FP16 texels (native -> amp repeats each texel K times; amp -> tube takes the amp sample under the host pixel centre, the same rule as the `beam_eval` stub). Tests: the identity holds bit-exact for all 256 codes with every slot on and every slot off.
- **Identity stages are skipped** (`Stage::is_identity(params, fc)`, default `false`; `Pipeline::plan_frame`). A stage says that, for this frame's parameters, its output equals its input bit for bit and that running it has no effect a later stage or later frame needs (no state buffer or history it would update, no probe texel). When the slot keeps its domain the pipeline routes around it exactly like a disabled slot (mode `Skip`): no pass, no image written, no barrier, no descriptor write, the next slot reads the previous image, and the timing segment is absent (`ms: None`, not `bypassed`). The test is re-evaluated every frame, so a parameter change re-routes at once (the images of a skipped slot are kept allocated and are written again when it runs; descriptor sets are rewritten only when their views change, as for a disabled slot). `Stage::prepare` is called with `runs` false for a skipped slot, the same hook as for a disabled one, so a stage with history restarts exactly as in the off to on transition (`phosphor`: history freed and the clear armed; `abl`: state clear armed, the first frame that runs again starts cold). A domain-changing slot (`amp`, `screen`) is never skipped: its output has another size, so an identity there still runs (the answer is ignored). Implemented for `phosphor` (`phosphor_persistence` and `phosphor_saturation` both off: saves the full-tube copy, 16 B per texel, 44 MB per frame at 1920 x 1440) and `abl` (`abl_enable`, `abl_breathing` and `abl_probe` all off: saves the full-image copy and the reduce pass; with the breathing on and the limiter off the slot runs, because the reduce pass keeps the state that `screen` reads for `raster_scale`). Not implemented, on purpose: `gun` (gamma 1 clamps negatives, `power_law` takes `max(v, 0)`, and an `amp` with peaking can undershoot, so it is not bit-exact in general, and the default gamma is 2.4), `amp` (a size change; its ideal case is already an early-out of the shader that equals the resample copy bit for bit). `abl`'s state clear now waits for the earlier reads of the state buffer (`screen` binds it in every frame, also while `abl` is skipped). Tests: `tests/pipeline_skip.rs` (pass count, toggling against a fresh pipeline, bursts with parameter flips under synchronization validation, ABL state with breathing on and limiter off); `Headless::last_chain_passes`, `last_skipped_slots`, `render_burst_params`.
- **`FrameConstants`** (std140, 60 bytes, `common.glsl`; a Rust test checks the offsets): tube rectangle in target pixels (x0, y0, x1, y1, whole pixels), native size, target size, px per mm and line pitch in mm (0 until T-30 places the tube), frame index, time since the previous frame in ms, `tube_size` and `amp_k` (T-20b). `FrameConstants::new` builds the unplaced defaults (the native raster letterboxed into the target, integer factors with `--integer`, px per mm and line pitch 0; stage tests start from it); `domain_size` gives the image size of a domain. **Tube placement (T-30, `src/placement.rs`):** the live and headless `record` use `FrameConstants::placed`, which maps the tube to the output from `params/tube.toml` and `params/source.toml` (PHY-3: all lengths in tube mm). Picture aspect = source width x PAR / source height (`raster_aspect = par`) or the tube aspect (`fill_tube`); the picture is the largest such rectangle of the visible area (full height, or full width when wider than the tube), its height is the raster height; s = min(target width / picture width, height fraction x target height / picture height) host px per mm (whole pixels per source row with `--integer`, when at least 1); line pitch = raster height / (native rows x `line_multiplier`); the tube rectangle is the picture, size rounded to whole pixels, centred, black surround outside. With the defaults (`par`, PAR 1, fraction 1) this is exactly the old letterbox (a test compares both over many sizes). The oracle is `crt-model/src/tube.rs`. Until T-37 (overscan, geometry) the raster fills the tube rectangle. `line_multiplier` only changes the pitch here: the beam stage (T-36a) reads `line_pitch_mm` and `params.line_multiplier`.
- **Placement and host scale modes** (T-30, T-96: PLAN D-13 and D-18; `src/placement.rs`, parameters `params/source.toml` and `params/tube.toml`, oracle `crt_model::tube`, tests `tests/placement_modes.rs` and `tests/stage_source.rs`). The CPU maps the native raster to the output once per frame (`FrameConstants::placed`): picture aspect A (`par`: native_w x `source_par` / native_h; `source_display_aspect` > 0 forces it; `fill_tube`: the tube aspect), raster (Wr, Hr) in tube mm, then a scale s in host px per mm. `source_scale_mode` = `tube` (default, unchanged since T-30): s = min(target_w / Wr, `tube_height_fraction` x target_h / Hr), optionally whole px per row (`--integer`). The host modes size the picture against the actual output, never an assumed resolution: k host px per source row with `native` k = 1, `integer` k = `source_scale` (0 = the largest whole number that fits), `fit` the largest whole number that fits (free below 1), `fit_free` k = min(target_w / (native_h A), target_h / native_h); a whole k that does not fit is reduced, a source larger than the output is downscaled, both reported. Then s = k native_h / Hr, so the scanline pitch is k / `line_multiplier` host px and the mask is `mask_pitch_mm` x s px per triad: the physical model stays consistent and only its host sampling changes. The picture is round(k native_h A) x k native_h px (with PAR 1 exactly k x k px per source pixel), centred (or top-left, `source_center` off). Outside the tube rectangle the output is `source_surround_color` (the clear colour of `encode`, whose draw is scissored to the tube rectangle; black by default). `placement::readout` resolves it all for the UI (mode, px per source px, integer alignment, picture and offsets, px per mm, scanline px, px per triad, mask tiers, fit) and `--stats` prints it. The crop (`source_crop_mode`: client area, manual rectangle, whole window) and the divisor (`source_divisor_mode`: detected, manual, none) are resolved by `scaling::SourceMap`; all of these are stored in the source profile (`settings.rs`, keyed by executable and class) and applied when the target is attached; command-line options override the profile.
- **Barriers:** every pipeline image tracks its last recorded access (layout, stages since the last barrier, pending write access). Each barrier takes its source scope from that state: a discarding write (`UNDEFINED` -> `GENERAL` or `TRANSFER_DST`) waits for the previous readers and writers, in this frame or an earlier one; a read waits for the last write. Reads in `SHADER_READ_ONLY_OPTIMAL` are made visible to compute and fragment together. Since the queue executes frames in recording order, this orders frames in flight too. A test readback goes through `Pipeline::prepare_readback`, tracked the same way.
- **Descriptor sets:** per frame slot, one set for `decode`, one for `encode`, one per slot pass and one per domain-changing slot (its resample bypass), allocated from a pool sized from the chain. Input and output bindings are rewritten only when the routed images change (enable flags, reallocation).
- **Frames in flight:** 2 slots. Each slot has its own command buffer, fence, staging upload buffers, `FrameConstants` and `Params` uniform buffers and descriptor sets; the CPU writes a slot only after waiting for its fence. Headless burst tests submit overlapping frames under synchronization validation, with the chain on and off.
- **Reallocation:** `src` and the staging buffers follow the capture size, `native` the native size, each slot output its domain size. A change idles the device, recreates the image and invalidates the bindings of every frame slot. A new image starts `UNDEFINED`: history is cleared on a mode change (SRC-8); later history images follow the same rule.
- **Stage-test helpers** (`Headless`): `render_stages(&StageRun)` renders one frame with injected `FrameConstants` (used as given: K, tube size, px per mm, line pitch, frame time) and an input that is either a captured frame or a float image injected as the output of `decode` or of any slot (`StageInput::Image { after, image }`, FP32 on the GPU, size checked against the domain); `enable_only(&[...])` picks the stage subset; `Rendered::stage(name)` returns the image each slot left for the next (all read back). Tests compare those images with the `crt-model` oracle.
- **Beam, vertical profile** (T-36a, `include/beam.glsl`, parameters `params/beam.toml`): the scanline raster fills the tube rectangle vertically, centred; line pitch P = `line_pitch_mm * px_per_mm` host px; line multiplier m = round(tube height / (P x native rows)), clamped to [1, 16]; line n draws native row n / m. Per host pixel, the lines within +/- 4 sigma_max are summed, each weighted by the fraction of its unit-area profile (Gaussian core, sigma = `beam_fwhm_mid_mm` / 2.3548 x px per mm, plus a tail of weight `beam_tail_weight` and sigma `beam_tail_sigma_ratio` x sigma) inside the pixel's rows (erf, area integration), times P: a flat field of current I has mean light I for any sigma. While the tube is not placed (`px_per_mm` or `line_pitch_mm` 0) `beam_eval` falls back to the nearest amp sample, so the identity tests stay exact. Hooks used by the next bullet and by the geometry: `beam_line_current`, `beam_sigma_v_px`, `beam_sigma_max_px`, `beam_raster`. Oracle: `crt_model::beam::scanline_row_mean`; tests `tests/stage_beam_vertical.rs`.
- **Beam, horizontal spot and spot growth** (T-36b, `include/beam.glsl`, supersedes the "nearest amp sample" horizontal term above): along a line the current is held over each amp sample (sample j covers [j a, (j + 1) a) px, a = tube width / amp width). Each (line, sample) pair within reach draws a round 2D spot of the sample's current, per channel: FWHM² = d0² + k I^(2n) from `beam_fwhm_mid_mm` (I = 0.5^2.4), `beam_fwhm_peak_mm` (I = 1) and `beam_growth_exponent` (`beam_spot`, `beam_sigma_px`). Its light in the host pixel is i P X Y: X the exact box-Gaussian double integral over the sample box and the pixel columns (overlap plus four Gaussian terms H, no cancellation for far samples), Y the erf fraction over the pixel rows; core plus the optional tail in both axes. Lines and samples are visited within 4 sigma of the spot at twice the peak current; a run of equal samples on a line is one box (the inner Gaussian terms cancel exactly), evaluated only within 4 of its own widest sigma. Flat fields are unchanged and each sample keeps its energy, except the light that spills past the tube rectangle's ends. Hook for T-37: `beam_convergence_px` (per-channel landing offsets in px, zero). The screen stage is no longer an identity even at 1 px per source pixel, so tests of other stages bypass it. Oracle: `crt_model::beam::{SpotGrowth, box_gaussian_overlap, BeamOracle}`; tests `tests/stage_beam_horizontal.rs`. Cost (RTX A2000 Laptop, 1536 x 1440 tube at 6 px per line, K = 4, validation on, best of 5 frames on a shared GPU): 1.8 ms for full white (one run per line), 9.1 ms when every amp sample differs (worst case); with a 5 % tail 11.9 and 64 ms. Input for T-47 and T-48 (tail cost).
- **ABL and raster breathing** (T-35, PHY-13, `stages/abl.rs`, `include/abl.glsl`, `params/abl.toml`, oracle `crt_model::abl`, tests `tests/stage_abl.rs`). The per-frame global state lives on the GPU: a 16-byte storage buffer owned by the `abl` slot (set 1 of its passes; filtered APL `apl_f`, last frame APL), cleared by `vkCmdFillBuffer` in the first recorded frame (and after a skip); the clear seeds `apl_f` with `abl_breathing_ref` while the breathing is on, so `raster_scale` starts at exactly 1 (T-37 review), and with 0 otherwise (cold start on black). Per frame the slot records two passes: apply (output = input x g(apl_f), g = 1 / (1 + k max(0, apl_f I_fw - I_th)), k = (1/r - 1) / (I_fw - I_th)) then reduce (one workgroup of 256: FP32 mean of (I_r + I_g + I_b) / 3 of the unlimited current, then apl_f += (1 - exp(-dt / tau)) (a - apl_f) with dt = `frame_time_ms`; in every quality tier but `exact` (T-48) the sum is parallel: `reduce_partial.comp`, one workgroup per 4096 texels, partial sums after the state in the same buffer (set 1 binding 1, offset 256), then `reduce_final.comp` adds them and updates the state the same way; the APL differs by the FP32 rounding of the summation order only, `stage_abl::parallel_reduce_matches_the_exact_one`). The gain of frame N+1 comes from frame N (one frame of latency); no CPU readback and no wait (gate 10). The slot records the barriers on its own buffer (previous reduce -> apply, apply -> reduce); queue order covers the frames in flight. `raster_scale` = 1 + b (apl_f - ref) is `abl_raster_scale()` of `abl.glsl`; it is not in `FrameConstants`, which the CPU writes before the GPU measures the APL: the geometry stage (T-37) must either bind the ABL state or have the pipeline copy the value into its frame constants on the GPU (open point). `abl_probe` writes (g, apl_f, raster_scale, frame APL) into texel (0, 0) for tests.
- **Plugging in a stage** (T-30 to T-46): fill the slot's module (`stages/<slot>.rs`): replace `Placeholder` by a type implementing `Stage` (usually a `ComputePass` created from `shaders/<slot>.comp`, with a push-constant block if needed) and keep its `SLOT` registration; parameters come from the `Params` buffer. Screen-domain physics goes into `include/beam.glsl` and `include/mask.glsl` without touching `screen.comp`. A new slot is one module, its shader, its `mod` line and one line in `CHAIN` (a test-only `dummy` stage proves it).
- **Mask: aperture grille, slot mask, delta dot** (T-39a, T-39b, T-39c; `include/mask.glsl`, parameters `params/mask.toml`; A12, A14, PHY-2 option A): `mask_eval(q)` returns, per channel, the exact area mean of the emitter over host pixel q divided by the mean coverage (flat white has mean 1, a lit stripe reads 1 / fill), with the closed forms and conventions of the oracle `crt_model::mask` (T-38): stripes of pitch p = `mask_pitch_mm`, R, G, B centred at (c + 1/2) p / 3 from the left edge of the tube rectangle (from the tube centre since T-37, see the geometry bullet), width `mask_stripe_fill` p, linear edge ramp `mask_edge_softness` p (limited to the stripe and to 1/3 - fill); damper-wire shadows (`mask_damper_count`, `mask_damper_width_mm`, `mask_damper_edge_mm`) at 2/3 of the visible height for one wire, k / (n + 1) otherwise, measured from the top of the visible area (`tube_visible_height_mm`, the tube rectangle centred in it). The grille is separable: column term times row term. Tiers (`mask_tier`): `auto` area-integrates from 3 host px per triad and prefilters below (tier C: the column term is its mean over a full period, 1, so only the wires remain), `integrated` and `prefiltered` force one or the other. **The tier is per axis and decided on the CPU (T-39c, D-15):** `placement::mask_tiers` (f64, from the f32 px per mm and parameters, via `crt_model::mask::Mask::axis_tiers`) gives the horizontal tier (triad pitch against 3 px, box one triad) and the vertical one (slot V / 2, delta P / 2 against 2 px, box V or P; none for the grille), each `Integrated`, `Prefiltered` or `Blended { box_px }` inside the band `mask_tier_blend` (default 0.4 px per triad around 3, the same relative width around 2 vertically), where the box narrows linearly from one period to one pixel; `Pipeline::record_commands` writes it into the appended `FrameConstants::mask_box_px` (`with_mask_tiers`; 0 = whole period, else the box width in px) for every frame, injected ones included, and `mask.glsl` only reads it, so readouts and image agree exactly. The column phase is reduced exactly (integer arithmetic on the mantissa of the f32 pitch in host px, `mask_triad_phase`), so stripes do not drift across the screen: a plain f32 `fract(x / pitch)` is already outside the test budget at column 105. `mask_enabled` off, or a tube not placed (px per mm 0), gives exactly 1. `mask_type` is the 3-way enum (A12) switched in `mask_eval`: `mask_slot` (T-39b: the grille's triad columns cut by bridges, `mask_slot_period`, `mask_slot_bridge`; column k offset by half a slot period for odd k) and `mask_delta` (T-39b: dot triads on a diagonal lattice of pitch `mask_pitch_mm`, `mask_dot_fill`) have the same exact-area-mean contract as the grille. Defaults: mask on, no damper wire, so at the default density (1.54 px per triad, tier C) the default chain is unchanged. Tests `tests/stage_mask_grille.rs` (oracle comparisons within one FP16 step and an f32 budget, hand-derived numbers in the module header).
- **Geometry, skirt margin and mask origin** (T-37 and its merge with T-36c; `include/geometry.glsl`, `params/geometry.toml`, oracle `crt_model::geometry`, tests `tests/stage_geometry.rs`). `screen` binds the `abl` slot's state buffer read-only as set 1 (`Stage::abl_state`, `Stage::link_abl_state`, linked by the pipeline after creation; this settles the open point of the ABL bullet) and reads `raster_scale` from it only when the `abl` slot runs in that frame: the pipeline tells every stage after `prepare` (`Stage::set_abl_runs`) and `screen` passes it as a push constant; a disabled or skipped `abl` gives `raster_scale` 1, never a stale state. The beam reaches the geometry through three hooks: `geometry_footprint(q)` (raster position of the host pixel's footprint), `geometry_inv_magnification` (raster px per host px of the size step, 1 / ((1 + overscan) `raster_scale`) per axis: the footprint, the spot sigma and the convergence offsets are scaled by it, so the spot keeps its size in mm and a larger raster at the same beam current is dimmer by 1 / (mx my); the local magnification of the curvature (Lambertian, kept luminance) and of pincushion, trapezoid and rotation is not applied) and `geometry_convergence_px` (evaluated at the landing pixel, not at the source point: the model's source-point form is its first-order inverse, difference about 2 rad^2 r^3 / rc^4, 0.17 px at 2 mm in a 19 in corner at 1440 lines). **Visible opening** (T-37 review F1): the light is clipped to the tube's visible area (`tube_visible_height_mm` x `tube_aspect`: the raster rectangle at zero overscan, widened to the tube's aspect when a `par` picture is narrower or shorter than the tube) with rounded corners (`geometry_opening_corner_radius_mm`, CRT.md 15 to 40 mm on older tubes, default 0 = square): coverage clamp(0.5 - d, 0, 1) of the signed distance d of the pixel centre, exactly 0 half a pixel or more outside, antialiased over one host pixel across a curved outline, exactly 0 or 1 on the square opening of a placed tube (bit-exact inside). The skirt margin is still evaluated but lies outside the opening, so the picture's outer edge no longer depends on the spot size, overscan or `raster_scale`. **Not modelled (deferred, PHY-11):** S-linearity residuals (CRT.md gives the cause, beam position proportional to tan theta, and the residual size, 0.5 to 2 % of the height, but no residual profile: a one-parameter remap would be invented) and refraction through the faceplate (CRT.md names the ray cast through the outer surface, n about 1.53, but gives no outer radius or thickness per tube shape for the curved-glass case). **Standard beam quality under a geometry:** the T-36c tile path needs every pixel of a tile column to share its raster x and every pixel of a tile row its raster y. That holds for the raster margin, overscan, `raster_scale` and misconvergence (per-axis affine maps, `geometry_separable`): pass 1 takes the column's raster x and pass 2 the pixel's raster y from `geometry_footprint`, so the result is the reference one (exact without spot growth; with growth MAE 0.008 %, max 3.1 % of white with overscan, tests `stage_beam_fast::standard_follows_the_geometry`). **Standard-vs-reference contract (T-48):** mean absolute error <= 0.5 % of white and max <= 4 % of white, for any alignment of the pixel grid to the samples and lines (measured worst 3.22 to 3.32 % with overscan before the T-37 review, 3.13 % after it; 3.52 % with a 2 mm radial misconvergence); this replaces the 2.5 % max of T-36c, which held only at the identity alignment (2.04 % measured there). The radial convergence term is not in `geometry_separable`: the standard path takes the offset at the column and line centre, an error of at most rad x 0.48 / rc px per px (0.004 px per px at 2 mm on a 19 in tube). A curved faceplate, pincushion, trapezoid or rotation bends the raster's rows and columns across a tile; until T-91 the standard quality then fell back to the per-pixel reference form at the reference cost (T-47: 4.7 to 6.1 times the flat `screen`). Identity geometry keeps the fast path unchanged (bit-exact). Cost of the tile path (`screen` GPU time, RTX A2000 Laptop, 1536 x 1440 pixel art, mask tier C, best of 15 interleaved frames on a shared GPU, `stage_beam_fast::screen_profile_geometry`): identity standard 1.66 ms (reference 3.76); separable cases on standard: margin 7 px 1.95, overscan 3 % 2.01, red dx 0.3 mm 2.15, all three 1.92. **Skirt margin:** `Pipeline::record` (and `prepare`, same constants) grows the tube image by `FrameConstants::with_skirt_margin` (4 sigma at twice the peak current plus the largest misconvergence, limited by the room around the tube rectangle) whenever the `screen` slot runs; `tube_rect_px` grows with it, so `encode` draws the skirt and the surround starts past it. A bypassed `screen` (nearest resample) or an unplaced tube gets no margin. **Mask origin:** every mask lattice (grille, slot, delta) has its origin at the tube centre on both axes (`mask_centred_phase`: fract((2q - size) / (2 period)), exact with the integer reduction of `mask_triad_phase`, which now reflects negative coordinates exactly), so the mask does not move with the picture width (PAR) or the margin; damper wires stay at fractions of the visible height.
- **Warp path: curved geometry on the separable beam** (T-91, `shaders/screen_lines.comp`, `shaders/screen_warp.comp`, `include/beam_warp.glsl` (design and error bound), `stages/screen.rs`, tests `tests/stage_beam_warp.rs`). The beam is a sum over raster lines of a horizontal profile times a vertical one in raster space; only the raster position of a host pixel bends, not the profiles. With a non-separable geometry and the standard quality the `screen` slot records two passes instead of `screen.comp`: (1) `screen_lines.comp` writes the tile path's pass-1 entry (H = sum of i X over the runs within reach, and the sigma moments sum h sigma^2, sum h sigma^4, core and tail) of every raster line at raster columns on a uniform grid of `ox` entries per raster px (footprint width im_x, horizontal convergence where the entry lands, `geometry_seen_px`, the forward map) into five `rgba16f` line images owned by the stage (set 2; width (tube width + 2 pad - 1) ox + 1, height the raster lines; pad = the reach plus the misconvergence plus 3 px, so the host pixels at a curved edge, which see raster positions beyond the tube image, find the skirt; moments stored divided by sigma_max^2 and ^4); (2) `screen_warp.comp` maps each host pixel through the full geometry (`geometry_footprint`, the reference's footprint, curvature Lambertian as before), interpolates the entries of every line within reach at its raster x (Catmull-Rom for H, linear for the moments with the matching linear H) and integrates each line's profile exactly over the pixel's raster rows (`beam_y_line`, the tile path's pass 2), then the mask in tube coordinates (`mask_eval`, never warped) and the opening, as `screen.comp`. Vertically there is no sampling, so scanlines cannot alias at any magnification (a 2D raster-space image resampled bilinearly would err by up to 38 % of white on a scanline peak at 6 px per line, 9 % at twice the vertical resolution). Horizontally the CPU (`warp_plan`, per frame in `Stage::prepare`, from the parameters and constants) takes the smallest `ox` in {1, 2, 4} with the spot sigma at peak current >= 1.2 grid steps (`WARP_SIGMA_STEPS`; Catmull-Rom error at most about 1.2 % of white, 0.43 % for the PVM-20M4U spot at 1440 lines); a spot under 0.3 raster px keeps the reference form. The identity and the separable geometries record `screen.comp` alone, bit for bit and at the same cost, and allocate nothing (the per-stage form of `Stage::is_identity`: `screen` changes domain, so it is never skipped, and a separate `warp` slot would need a raster-space domain the image contract does not have); the line images are freed while the warp path is off; the stage records its own barriers on them (layout transition after an allocation, write-after-read before pass 1, write-to-read between the passes); the timing segment `screen` covers both passes. Accuracy against the reference (same geometry, PVM-20M4U growth, 960 x 720 tube at 6 px per line, 1R = 427 mm): spherical (eye at infinity, 600, 300 mm), cylindrical, pincushion +/- 0.02, trapezoid 0.03, rotation 1.5 deg, cylindrical with convergence and overscan, on pixel art, ramp, 1-px checker, flat white, 1-on-1-off columns and rows: worst MAE 0.055 %, worst max 3.71 % of white (pixel art, rotation; the tile path's spot-growth term at an arbitrary alignment, 3.5 % already under overscan); 5 % tail 3.47 %; no growth at ox 1 and 2 below 1 %; presets 01 and 05 at full size MAE <= 0.28 %, max <= 3.52 %. A flat field keeps its luminance I / ((1 + ov_x)(1 + ov_y)) on a curved faceplate (within 1.9e-4, FP16) and with the PVM spot (scanlines) the picture mean equals the reference's (0.912397 against 0.912398). Cost (`screen` GPU time, headless debug build with validation, best of 5 interleaved frames on a shared GPU, presets as shipped through `amp` and `gun`, K = 16, `stage_beam_warp::screen_profile_warp`): preset 01 (cylindrical) ramp / 1-px checker: 1558 x 1440 flat 7.43 / 8.65 ms, warp 2.65 / 2.99, reference (the old curved standard) 35.1 / 141; 1920 x 1440 flat 8.72 / 10.73, warp 3.32 / 3.70, reference 141 / 172; preset 05 (spherical): 1572 x 1440 flat 9.67 / 10.44, warp 3.77 / 3.73, reference 62.7 / 111; 1920 x 1440 flat 12.88 / 12.98, warp 4.73 / 4.63, reference 188 / 237. A curved tube now costs 0.35 to 0.39 times the flat tile path: the line image computes each (line, column) entry once (the tile path repeats the lines a tile's reach shares with its neighbours, about 1.7 times, and leaves about 70 % of its invocations idle in pass 1) and visits 3 to 5 lines per pixel instead of every line of the tile's chunk. The flat tile path is therefore the slower one now. **T-48 (2026-11-20):** from the `standard` quality tier on, an unscaled separable raster (flat tube, no overscan, no running ABL breathing; convergence allowed) takes these two passes too, on a grid aligned with the host columns (`ox` 1, column k = host column k - pad: every host pixel lands on a grid column, Catmull-Rom weights (0, 1, 0, 0), no interpolation whatever the spot size), so the entries are the tile path's computed once per (line, column); the only difference is their FP16 storage (measured within one FP16 step of the tile path: MAE 0.012 %, max 0.195 % of white). From `fast` on a scaled separable raster (overscan, breathing) takes them as well, interpolated as a curved one. The `exact` tier keeps the tile path. See "Quality tiers".
- **Phosphor persistence** (T-41, `shaders/phosphor.comp`, `gpu/stages/phosphor.rs`, parameters `params/phosphor.toml`; CRT.md rule 8, PHY-12): a frame feedback at the output frame rate `phosphor_frame_rate_hz` (60). Per channel, the Kuhn P22 impulse response (`crt_model::phosphor`, tail scaled by `phosphor_tail_strength_rgb`) is discretised per frame period T into four geometric terms (rho_j, c_j) by `DecayFit::frame_feedback`: exponential terms exactly (rho = exp(-T / tau)), the power-law trail fitted over the 1 s window, exact at 1, 2 and 3 frames (E_k / E_0) and within about 1 % up to 1 s. Shader: y = w0 (x + sum_j S_j), S_j <- rho_j S_j + c_j x, with w0 = 1 / (1 + sum_j c_j / (1 - rho_j)) so a static picture keeps its brightness exactly; terms below 2^-24 are flushed to 0. The weights are computed on the CPU when the rate or a tail strength changes and pushed as push constants (116 bytes). **Stage-owned history** (the contract's exception): the stage allocates three RGBA32F images of the tube size (4 terms x 3 channels; FP32 because FP16 truncating stores would bias the slow term), its own descriptor set (set 1) and pipeline layout (set 0 is the standard set, shared with its copy pass), and records its own barriers on them (layout transition after an allocation, then a compute-to-compute memory barrier per frame). Two `Stage` hooks with default no-ops serve this: `prepare` (called by `Pipeline::record_with` for every slot once the routing is known, with `runs`; may idle the device and allocate) and `clear_history` (`Pipeline::clear_history`, `Renderer::clear_history`, `Headless::clear_history`). The history is cleared after an allocation (tube size change), on `clear_history` (the window loop calls it when `SizeWatch::take_history_clear` reports a source size change or a new capture session, SRC-8) and when the slot did not run on the previous frame; it is freed while persistence is off. Tests `tests/stage_phosphor.rs` (derivations in the module header).
- **Faceplate optics** (T-45, `gpu/stages/optics.rs`, `shaders/optics.comp` and `optics_{down_input,down,kernel,diffuse,gauss_h,gauss_v}.comp`, `include/optics.glsl`, parameters `params/optics.toml`, oracle `crt_model::optics` with the model and its derivation, tests `tests/stage_optics.rs`; CRT.md rule 7, QUESTIONS PHY-10). Model, all redistributions of the emitted light L (a full white field keeps its level away from the edges): D = (1 - w_d) L + w_d G_sigma * L (phosphor-layer diffusion), G = (1 - w_h - w_g) D + w_h K * D + w_g mean(D) (halation halo K, veiling glare), out = v^(rho^2) tint G + ambient (vignette, glass tint, diffuse room light E (T tint)^2 r_s / (pi L_w)). The halo kernel K is derived from the glass (Lambertian emission, glass-side Fresnel reflectance rising to total internal reflection at asin(1 / n), return at 2 t tan(theta), absorption T^(2 / cos(theta)); edge at 1.747 t, inner Fresnel haze, tail truncated at 99 % of its energy); its amplitude is the parameter `optics_halation_weight`. Passes per frame (CPU plan `optics::plan`, re-evaluated every frame): a zero-padded 2 x 2 box pyramid to 1 x 1 when the halo or the glare is on (its top times 4^n / (W H) is the mean), the halo by `optics_halo_method` (`kernel`, the default chosen by the T-44 study: the kernel as cell masses on the finest level whose texels keep it within `optics_halo_taps` (24) texels, a direct sum with the weights in shared memory, read bilinearly; `pyramid` and `gaussians` kept for comparison), the horizontal half of the diffusion (radius <= 16 px), then the composite (vertical half of the diffusion, halo, glare, vignette, tint, ambient; `round_f16` store). The stage owns its images (pyramid levels, kernel halo, diffusion image, the gaussians images, a 1 x 1 stand-in for unused bindings; set 1 with 18 storage-image bindings and a storage buffer) and records its own barriers (layout transition of new images, one memory barrier from the previous frame, one between passes); the kernel cell masses and diffusion weights are computed on the CPU when their inputs change and written to a host-visible buffer after a device idle. `Stage::is_identity`: `optics_enable` off (default, D-6, D-24), px per mm 0, or every effect neutral. Measured (QUESTIONS PHY-10, headless bursts at 1920 x 1080, 4.966 px/mm, every effect on, 5 % halo, 2 px diffusion; a clock-limited shared laptop GPU, +/- a factor 2 to 3): kernel method 1.05 to 1.14 ms for the whole slot (about 0.4 ms at the best clocks), error against the oracle MAE 0.010 %, max 0.13 % of white; pyramid method MAE 0.24 %, max 1.9 %; gaussians 64 ms. Limit: a single-pixel source has its ring edge smeared over one cell (32 px at 4.966 px/mm). Presets 01 to 09 carry faceplate values but leave the stage off.
- **Ageing and burn-in** (T-42, T-43, QUESTIONS PHY-14, SCP-6; `gpu/stages/wear.rs`, `shaders/wear.comp`, `shaders/wear_accumulate.comp`, `params/ageing.toml`, `params/burnin.toml`, `src/ageing.rs`, `src/tube_state.rs`; oracles `crt_model::ageing` and `crt_model::burnin`; tests `tests/stage_ageing.rs`). cathode wear in `gun.comp` (I = (1 - `ageing_cathode_loss_rgb`) law(V - `ageing_cutoff_drift_rgb`)); spot growth by `ageing::effective_params`, which the pipeline applies at its three entry points (`record_ui`, `record_with`, `prepare`) so that every CPU and GPU user of the spot law sees the grown widths. **Slot `wear`** (between `screen` and `phosphor`: its input is the light of a fresh phosphor, the charge proxy; The stage records its own barriers (previous accumulation and one-time copies before this frame's accesses; apply before accumulate). CPU operations (`Wear::set_map`, `reset`, `read_now`) idle the device and run a one-time command buffer in `prepare` or between frames; the periodic save is asynchronous: `request_snapshot` makes the next frame copy the map into a host buffer and set a `VkEvent`, `take_snapshot` polls it without waiting. **State file** (`tube_state.rs`): `%APPDATA%\ultimateCRT\tubes\<preset>.state` (`default` without a preset), little endian: magic `UCRTWEAR`, u32 version 1, u32 width, u32 height, u32 channels 3, 8 reserved bytes, then width x height x 3 f32 charges, then a CRC-32 of everything before; atomic write (`.tmp`, flush, rename); a missing file is a new tube; a bad magic, version, size, checksum or a negative or non-finite charge gives a new tube, a warning and a `.bak` copy; another size is resampled bilinearly. **Controller** `TubeState` (render thread, `app.rs`): while `burnin_enable` is on, loads the map of the preset in force at the first frame and when the preset changes (the old map read back and saved first), requests a snapshot every 5 minutes and writes it on a background thread, saves at exit (blocking read once); the menu buttons "Burn in N h now" and "New tube (reset wear)" (panel "Ageing and burn-in", `ui::WearAction`) and `--reset-burnin`. - **Interlace, manual field mode** (T-32, QUESTIONS SRC-7; `params/interlace.toml`, `shaders/include/interlace.glsl`, the raster of `beam_raster` in `include/beam.glsl`, `gpu/stages/screen.rs`, `src/interlace.rs`; oracle `crt_model::interlace` with the model; tests `tests/stage_interlace.rs`). Optional, off by default (A15, A21). A capture has no field parity, so the user declares it: `interlace_mode` `alternate_frames_are_fields` (each captured frame is one field; the bottom field is the progressive raster moved down by P / 2, the top field keeps the progressive position, so a locked top field is today's 240p double strike) or `split_woven_frame` (the captured frame is a woven frame; field f draws rows f, f + 2, ... at their progressive positions: a raster of pitch 2P from first + f P, each line depositing current x 2P, so one field of a flat field keeps its mean; with a locked field this is the 240p double-strike look of that field). The field of an output frame is the parity of the pipeline's frame counter (`FrameConstants::frame_index`), inverted by `interlace_field_order = bottom_first`, or locked by `interlace_field_select` (`top`, `bottom`, for inspection): each output refresh shows one field, and the decay between fields is the persistence stage's (T-41). Only `beam_raster` changes (first line, pitch, line count, and the row a line draws, `beam_line_row`), so the reference, standard (tile) and warp paths all follow. **Bit-exact off:** the field code sits behind the specialization constant 0 `UCRT_INTERLACE`; `screen` creates its three pipelines with it false (the progressive raster alone) and the three variants with it true on the first frame with interlace on (`Stage::prepare`), and binds those while interlace is on. A plain branch on the parameter made the driver compile the progressive code differently (12 FP16 values of 3.7 million flipped by one step on preset pvm-20m4u, checker:1); with the constant the offline renders of 11 presets and patterns are byte-identical to the build without the module. The headroom readout uses the field pitch 2P for a split woven frame. The live loop shows a notice (title and console) when interlace alternates fields and the output refresh does not match the field rate (`crt_model::interlace::rate_notice`: capture rate against output rate for alternate frames, output against 59.94 or 50 Hz for a woven frame, 5 % tolerance). Field parity follows the output frame counter, not the capture: a dropped or repeated capture frame swaps the parity until the user flips the field order.

The other overrides stay in the generated "Source and placement" panel.
- **Picture area** (A25, superseding A24; `bars.rs`, owner requirements 2026-11-20). Three modes per program and class, `bars::AreaMode::of` from the parameters and the profile: **Auto** (default: `source_crop_mode` auto and no `picture_area = "client"`), **Manual** (`source_crop_mode` manual, the profile's `crop` with `crop_client`, the client size it was set for), **Whole client area** (`picture_area = "client"`). Crop mode none (the whole window) reads as Whole client area and disables the controls. Profiles of the first design load as they were: `crop_mode` auto is Auto, a detected crop is Manual.
  - **Detection** (`bars::Accumulator`, count-based with corner zones since A26): a pixel is lit when its brightest channel (BGRA and RGBA alike) is above the tolerance (default 8 codes). Per frame the lit pixels of every row and every column are counted, and per row and column the largest count of any frame of the window is kept, plus the darkest and brightest value. The four **corner zones** (`bars::corner_zone`: 48 px squares, at most 15 % of each axis) are left out of the counts and of the black and flat tests: Windows 11 rounds the window corners and Windows.Graphics.Capture delivers the anti-aliased rounding with the client area. A row or column is **picture** only when its count reaches `bars::min_count` (2 px, or 0.5 % of its length when more: 5 px of a 1100 px row), so isolated lit pixels (a hot pixel, a 1 px cursor, the rest of the corner anti-aliasing) cannot make a line picture, while a real line of content (hundreds of pixels) still counts. A frame where no row or no column reaches its count is "nothing to detect" (as black). The leading and trailing runs of non-picture lines are the bars, each side on its own; bars thinner than the minimum (default 2 px) are ignored; a frame black or flat everywhere is "nothing to detect"; with the divisor in force the picture keeps its origin and its size drops to whole source pixels. **Guard rails**, per axis: the bars may remove at most `bars_largest_crop` (default 97 %), and the picture left must be at least 16 source pixels and 2 % of the axis; a blocked axis stays uncropped and the reason is returned (`bars::Blocked`, shown in the Source message: "the bars would remove 99 % of the width, more than Largest crop allows" or "the picture would be only 10 px wide"). The first design's limit, 60 %, was the cause of the failed live test (QUESTIONS CAP-6). The single-pixel rule of A24 and A25 (a line was picture as soon as one pixel was lit) was the cause of the second one (CAP-7): the rounded bottom corners lit the last rows and the outermost columns of a real capture, so only the top bar was found. The real frame is a test fixture (`tests/data/capture-1to1-1100x800.png`), and `bars::single_pixel_bars` keeps the old rule for the comparison.
  - **Diagnostic** (`ultimatecrt --detect-bars <png>`, offline, no window, `app::detect_bars_report` -> `bars::report`): runs the detector with the settings' thresholds on a `--save-capture` PNG (decoded to the capture's BGRA layout) and prints the thresholds, the corner zone, per edge the dark lines, the largest lit count among them and the count of the first picture line, the outcome (picture and bars, or why nothing was cropped) and what the old single-pixel rule found.
  - **Auto** (`bars::Auto`, a pure state machine, unit tested): a full detection (`bars::Session`: 30 frames, or 1 s with a frame, or 3 s without) runs at attach (the frame on screen counts), when the captured client size changes (the Auto area is dropped until it ends) and on Detect now or Back to Auto (the area in force stays until the answer, `Auto::seed`); a verdict applies at once. Between detections, frames are sampled at most every 0.25 s and never more than 2 % of the time (the interval grows with the measured cost of a frame; `--stats` prints frames sampled and ms per second) into 2 s evaluation windows, only while frames arrive. An evaluation whose own outcome is black, flat or blocked is no verdict: nothing changes and it does not count. A larger or moved area is followed after 3 evaluations in a row (their last two windows merged); a smaller one only when the maxima of the last 30 s of verdict windows give it (the bars stayed dark all that time). After a black start the first verdict applies. The Auto rectangle is not stored: `app::run` overlays it on the resolved source map (`eff_map`), so the region, the integer-scale detection key (which includes the crop), the placement and the readouts follow it, and a change sets `remap`.
  - **Manual limits** (`bars::Bars` as left, top, right, bottom px cropped from the client area): `bars::edit_limit` clamps an edit (the picture at least 8 x 8 px, inside the frame, the opposite side kept) and, with a divisor known and Snap to source pixels on, moves it so the extent is a whole number of source pixels (the nearest; nudges step one source pixel). The menu sends `SourceAction::SetLimits`; the app makes it a manual crop (`bars::set_manual_crop` with the client size) and saves the profile debounced (`Live::save_source_profile(.., true)`); consecutive limit edits are one Undo step (`bars::CropState`, which also holds `picture_area` and `crop_client`). Choosing Manual starts from the area in force. The limits are absolute pixels, stored with the client size they were set for (`crop_client`). **Stale stored limits** (`bars::stale_manual`: Manual from the profile, not `--crop`, and a captured client size other than `crop_client`) are not applied: the app detects the picture area as in Auto (`bars::detects` gates the Auto feed and tick, `bars::crop_in_force` gives the crop in force), the profile keeps Manual until the user changes it, the combo reads "Manual (stored)", the line under it "stored limits not applied, detected", the callout gives both sizes (`AreaView::set_for`) and Back to Auto is offered; the console says so at attach (`app::report_stored_area`). Limits stored without a client size (older profiles) apply as before.
  - Settings (`[global.source]`): `bars_tolerance`, `bars_min`, `bars_largest_crop` (0.10 to 0.99). The first design's `bars_max_crop` and `detect_bars_at_attach` are no longer fields: serde ignores them at load and the next write drops them, so a stored 0.6 cannot survive.
  - **Show picture area outline** (owner's optional item): not built. The menu does not show the captured source picture anywhere (the picker's preview is in the picker only), so there is no place to draw it.
- **Scaling multiplier** (`scaling::Multiplier`): Auto (detected, the default), None (the capture is native) or x1 to x10, per axis under Advanced. It is the divisor mode with the manual divisor: the choice is written to `source_divisor_mode` and to the profile (`divisor_mode`, `divisor`, `divisor_v`), any `--divisor` stops winning, the source map is resolved again and the view (native size, placement, readouts) is recomputed at the next loop even without a new frame. The integer-scale detector now runs on every capture until it locks, also under a forced value, so the section always shows what was detected and a hint when the forced value disagrees ("detected x3, forced x2").
- **Not verified live:** the focus behaviour of the picker on a real desktop, previews and icons of real windows (a capture border may flash on the previewed window where `IsBorderRequired` cannot be turned off), minimised and cloaked windows, multi-monitor numbering. The black-bar detection is tested on synthetic frames and one real capture of pixel-demo (A26), the multiplier on headless menus only: real games with bars, dark scenes, fades and animated borders are not checked yet.

## 5. Target pipeline (partly built)

Stages in the order physics applies them (details in `CRT.md`). Built today: steps 1 (source decode, composite video (T-31, off by default), amplifier bandwidth, peaking), 2, 3, 4, 5 (persistence, saturation, ageing and burn-in), 6 (optics, T-45, off by default) and 7, and interlace (T-32, off by default; drawn by the beam raster of step 3, not in step 1).

This follows "Suggested physical pipeline order" in `CRT.md`, the authority if the two differ.

1. Source decode: native raster, source curve to code values, pixel aspect ratio. Optional signal module in the voltage (gamma-encoded) domain: composite encode and decode, amplifier bandwidth with rise and fall asymmetry, peaking, interlace field mode. Filtering horizontally before the gun law is what makes isolated vertical lines dimmer than horizontal ones.
2. Gun law per channel (brightness, contrast, cutoff, gain, power law around 2.4), then automatic beam limiting (gain from the frame's average level, low-passed in time). Gives the beam current per channel.
3. Beam: Gaussian-plus-tail profile in y per scanline, horizontal spot width, both depending on current and position, per-channel convergence offsets, and geometry (curvature, pincushion residuals, blooming scale).
4. Mask: integrate the beam over each phosphor element of the chosen mask type, prefiltered to the host pixel footprint (area-averaged), times element shape and fill factor. Phosphor saturation.
5. Phosphor: temporal decay per colour (frame feedback), ageing and burn-in wear map.
6. Optics: layer diffusion, halation ring, veiling glare, vignetting, glass tint.
7. Output: phosphor primaries and white to the host display primaries in linear light, exposure, SDR encode with a final dither.

Each stage has an enable flag so it can be bypassed or A/B compared.

Cross-cutting plans: one declarative parameter table shared by Rust, GLSL and the UI; three layered text profiles (tube, host display, source) with schema version and confidence fields; a tube-state file for the wear map; GPU timestamps per stage and a stats overlay.

## 6. Known risks

Tracked in `QUESTIONS.md` ("Risks that could invalidate the project"). The ones that shape the architecture today:
- **Hybrid graphics (HW-3):** capture and Vulkan are now created on one chosen adapter (3.5), but the captured game, the compositor and the monitor the output covers may still sit on other adapters; those crossings are done by Windows. Measured 2026-11-19 (3.5, QUESTIONS HW-3): frames flow in every combination; the RTX holds 60 fps presenting on the Intel monitor, while the Intel UHD running the chain captures 40 to 42 fps; the latency of a crossing is not measured.
- **One screen (OUT-1, CAP-4):** a covered source may stop delivering frames. Early test: with the demo, capture kept about 60 fps under a fullscreen output. A real game is not yet tested.
- **No-focus present (OUT-2):** whether the compositor adds latency or disables independent flip is not measured.
- **Unmeasured physics:** most constants in `CRT.md` are estimates and stay tagged until replaced.
